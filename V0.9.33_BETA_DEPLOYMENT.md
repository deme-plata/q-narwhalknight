## 🎯 Fixes Included in v0.9.33-beta

### Fix 1: SSE Balance Broadcast for Real-Time Updates

**Problem**: Master account balance updates correctly in backend but frontend doesn't receive real-time updates. Balance appears as zero for 20 seconds until page refresh.

**Root Cause**: Coinbase transaction processing at `main.rs:4034` only logged balance updates but NEVER broadcast SSE events to frontend.

**Solution**: Modified `crates/q-api-server/src/main.rs:4020-4074`
- Collect balance updates in Vec while holding mutex
- Release mutex before broadcasting (prevents deadlock)
- Broadcast SSE event for each wallet balance change
- Distinguish between "development_fee" and "mining_reward" based on wallet address

**Expected Result**:
- Frontend receives instant balance updates via SSE
- No 20-second delay
- Logs show: `📡 [SSE] Balance update broadcasted for wallet: efca1e8c1f46e910...`

---

### Fix 2: Phase5 Topic for Block Pack Requests

**Problem**: Node configured for `Q_NETWORK_ID=testnet-phase5` but block pack requests still using hardcoded `/qnk/testnet-phase4/block-pack-requests` topic. This causes TURBO SYNC to fail with InsufficientPeers and fall back to slow HTTP sync (~1 block/second).

**Root Cause**: Two locations in `main.rs` using hardcoded `NETWORK_ID` constant:
- Line 1850 ❌ (now fixed ✅)
- Line 2954 ❌ (now fixed ✅)

**Solution**: Modified both locations to:
```rust
// ✅ v0.9.33-beta: Use configured network ID (not hardcoded phase4)
let network_id = std::env::var("Q_NETWORK_ID")
    .ok()
    .and_then(|s| s.parse::<q_types::NetworkId>().ok())
    .unwrap_or(q_types::NetworkId::Testnet);
let topic = network_id.block_pack_requests_topic();
```

**Expected Result**:
- Block pack requests use `/qnk/testnet-phase5/block-pack-requests`
- TURBO SYNC works correctly
- Sync speed improves from ~1 block/second (HTTP) to ~100 blocks/second (TURBO SYNC)
- Logs show: `📤 [TURBO SYNC] Sent gossipsub request for blocks X-Y`
