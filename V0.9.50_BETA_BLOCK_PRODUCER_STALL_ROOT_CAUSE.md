# v0.9.50-beta - Block Producer Stall Root Cause Analysis

**Date**: 2025-11-08
**Status**: 🔍 **ROOT CAUSE IDENTIFIED**
**Severity**: P0 - CRITICAL (Recurring production outage)
**Versions Affected**: v0.9.8-beta through v0.9.49-beta

## 📋 Executive Summary

**Block producer is stalled at height 15511 despite active mining** due to hardcoded IPFS replication database path that doesn't match the actual database location configured via `Q_DB_PATH` environment variable.

**Impact**: Complete block production freeze, mining rewards not distributed, network stalled.

## 🔗 How This Causes Block Production Stall

### Timeline of Failure

```
01:29:17 UTC - IPFS replication runs (every 5 minutes)
01:29:17 UTC - Attempts to backup "./data/q-narwhal-db" (WRONG PATH)
01:29:17 UTC - Tries to open "./data/q-narwhal-db/CURRENT" (FILE NOT FOUND)
01:29:17 UTC - RocksDB error: "No such file or directory"
01:29:17 UTC - Database write lock MAY BE HELD by IPFS task
01:30:13 UTC - Block producer STALLED (60 seconds without height change)

01:30:13 UTC - ERROR: Height unchanged for 60 seconds: 15511
01:30:13 UTC - ERROR: IMMEDIATE ACTION REQUIRED: Service needs restart
```

### Causal Chain

1. **IPFS snapshot broadcaster runs** (every 5 minutes via tokio interval)
2. **Acquires database write lock** (`storage.write().await`)
3. **Calls `backup_database("./data/q-narwhal-db")`**
4. **RocksDB tries to open `CURRENT` file** at wrong path
5. **File not found error** (database is at `./data-mine5` not `./data/q-narwhal-db`)
6. **Write lock held** while error handling occurs
7. **Block producer can't save blocks** → height frozen at 15511
8. **Mining submissions queued** but never processed into blocks
9. **Network stalled** - no blocks produced despite active mining

### Solution 1: Pass DB Path to Replication Manager (PROPER)

**Step 1**: Add `db_path` field to `DatabaseReplicationManager`

```rust
pub struct DatabaseReplicationManager {

    /// Database path (v0.9.50-beta: Make configurable)

    // ... rest of fields
}
```

**Step 2**: Update constructor

```rust
// crates/q-ipfs-storage/src/replication.rs:114-132

pub fn new(
    node_id: Vec<u8>,
    storage: Arc<RwLock<Option<IpfsRocksStorage>>>,
    config: ReplicationConfig,
    db_path: String,  // ← ADD THIS PARAMETER
) -> (Self, mpsc::UnboundedReceiver<DatabaseUpdate>) {
    let (update_tx, update_rx) = mpsc::unbounded_channel();

    let manager = Self {
        node_id,
        storage,
        config,
        db_path,  // ← STORE IT

        update_tx,
        received_sequences: Arc::new(RwLock::new(HashSet::new())),

    };

}
```

## 🔍 LESSONS LEARNED

### What Went Wrong:

1. **Hardcoded Assumptions**: Code assumed fixed database path structure
2. **Incomplete Fix**: v0.9.8-beta "fix" just changed hardcoded value
3. **No Configuration Abstraction**: Database path not centrally managed
4. **Missing Integration Tests**: Path mismatch not caught in testing
5. **Silent Failures**: IPFS errors logged as WARN not ERROR
6. **No Path Validation**: System didn't validate paths exist on startup

### What Should Have Been Done:

1. **Single Source of Truth**: All components get db_path from same source
2. **Configuration Validation**: Startup checks verify paths exist
3. **Integration Tests**: Test different path configurations
4. **Fail Fast**: Invalid paths should ERROR not WARN
5. **Documentation**: Clear explanation of path requirements
