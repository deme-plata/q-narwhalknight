# v0.6.4-beta: Sync-Down Protection Fix

**Date:** November 1, 2025, 20:00 CET
**Status:** 🔨 Building
**Issue:** CRITICAL - Sync-down protection causing ERROR spam and blocking block production

---

## 🐛 Bug Analysis

### Problem Description
The sync-down protection added in v0.6.0-beta has a critical flaw that makes it **too aggressive**, causing massive ERROR log spam and appearing to block sync progress.

### Root Cause
**File:** `crates/q-api-server/src/main.rs:3081-3089`

```rust
// ❌ BROKEN v0.6.3-beta logic:
if network_height < current_height && current_height > 1000 {
    error!("🚨 CRITICAL: Sync-down attack detected!");
    error!("   Current height: {}, Network claims: {}", current_height, network_height);
    error!("   REFUSING to sync down - this would delete {} blocks!", ...);
    continue; // ❌ SKIPS ENTIRE LOOP - blocks all processing!
}
```

**What Happens:**
1. Node produces blocks faster than peers → gets ahead (e.g., height 2656 vs network 2648)
2. Sync-down protection triggers **every 100ms** (10 times/second)
3. Logs 10-100+ ERROR messages per second
4. The `continue` statement skips the entire sync loop
5. Appears "slow" but is actually just spamming errors

### Evidence from Logs

**Error Spam** (`looksgoodbutslow.ini`):
```

2025-11-01T18:52:02.785681Z ERROR q_api_server:    Current height: 2656, Network claims: 2648
[... hundreds more in 1 second ...]
```

**Actual Sync Performance** (very fast!):
```

```

**Block Production Working:**
```

🎉 Producer #0 created block at height 14
[... 8 producers creating blocks every 3 seconds ...]
```

### Key Insight
**The node is NOT slow** - it's syncing at 7000+ blocks/sec! The problem is:
- Error spam makes logs unreadable
- `continue` statement prevents normal processing
- Being AHEAD of network is **NORMAL** (we produce blocks faster)
- Sync-down protection should protect against attacks, not normal operation

## ✅ Fix Implementation

### Changes Made
**File:** `crates/q-api-server/src/main.rs:3081-3097`

**Before (v0.6.3-beta):**
```rust
if network_height < current_height && current_height > 1000 {
    error!("🚨 CRITICAL: Sync-down attack detected!");
    error!("   Current height: {}, Network claims: {}", current_height, network_height);
    error!("   REFUSING to sync down - this would delete {} blocks!", ...);
    continue; // ❌ BLOCKS ENTIRE LOOP
}

if network_height > current_height + 5 {
    // Sync logic...
}
```

**After (v0.6.4-beta):**
```rust
let mut last_sync_down_warning = std::time::Instant::now(); // Rate limiting

if network_height < current_height && current_height > 1000 {
    // Only log ONCE per minute (not 10 times/second)
    if last_sync_down_warning.elapsed() > std::time::Duration::from_secs(60) {
        warn!("⚠️  Node ahead of network: Current height: {}, Network claims: {}",
              current_height, network_height);
        warn!("   This is normal if we're producing blocks faster than peers.");
        warn!("   If this persists for >10 minutes, may indicate network partition.");
        last_sync_down_warning = std::time::Instant::now();
    }
    // ✅ DON'T skip loop - just don't sync down
}
// Changed to "else if" - only sync if we're BEHIND
else if network_height > current_height + 5 {
    // Sync logic...
}
```

### Fix Benefits

1. **Stops ERROR Spam** ✅
   - Changed from ERROR to WARN level
   - Rate limited to once per 60 seconds (not 10x/sec)
   - Clear explanation that being ahead is normal

2. **Allows Normal Processing** ✅
   - Removed `continue` statement
   - Changed to `else if` for sync logic
   - Block production continues uninterrupted

3. **Maintains Security** ✅
   - Still prevents sync-down attacks
   - Still validates network heights
   - Still protects against data loss

4. **Better User Experience** ✅
   - Logs are readable
   - Clear messaging about normal vs abnormal behavior
   - Only warns if persistent (>10 minute network partition)
