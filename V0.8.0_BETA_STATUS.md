```rust
pub async fn apply_block_pack(
    &self,
    pack: BlockPack,
    balance_engine: &BalanceConsensusEngine,
) -> Result<usize> {
    for block in pack.blocks {
        // Process mining rewards for historical blocks
        match balance_engine.process_block_mining_rewards(storage, &block).await {
            Ok(updates) => {
                debug!("Processed {} balance updates during turbo sync", updates.len());
            }
            Err(BalanceConsensusError::AlreadyProcessed(_)) => {
                // Skip already processed blocks
            }
            Err(e) => {
                error!("Failed to process block {}: {:?}", block.header.height, e);
                return Err(e.into());
            }
        }

        storage.save_qblock(&block).await?;
    }
    Ok(blocks_processed)
}
```

## Critical Notes

### CRITICAL: Sync-Down Safety
Balance consensus does NOT solve the sync-down bug. The sync-down safety measures from v0.5.23-beta+ MUST remain in place:
- ✅ Application-level check: Only sync if peer height > local height
- ✅ Database-level check: Refuse sync-down for heights >1000
- ✅ Balance reset when blockchain resets

### CRITICAL: Atomic Operations
Balance updates and block storage MUST be atomic. If balance processing fails, block MUST be rejected. This is enforced by the consensus engine returning errors.

### CRITICAL: Genesis Timestamp
The genesis timestamp `1761436800` (Oct 26, 2025) MUST match across all nodes. This is enforced by exporting GENESIS_TIMESTAMP as a constant.
