## 🎯 What This Release Fixes

### Problem 1: ERROR Spam (from v0.6.0-v0.6.3)
**Issue:** Massive ERROR log spam when node is ahead of network
```
🚨 CRITICAL: Sync-down attack detected!
   Current height: 3191, Network claims: 3189
   REFUSING to sync down - this would delete 2 blocks!
[... 100+ times per second ...]
```

**Fix:** Rate-limited to WARN once per 60 seconds (v0.6.4 fix included)

### Problem 2: Slow Batch Sync (User's Main Concern)
**Issue:** Only 80 blocks/sec = 4,800 blocks/min despite optimization work
**User Quote:** "we have worked for hours and days optimizing the block sync with git clone inspiratoin and what not. how come i only get 12 blocks minute"

**Root Cause Analysis:**
- Gossipsub default limit: 65KB
- Current batch utilization: 48.7% (only 32KB of 65KB used)
- Postcard serialization: ~395 bytes/block (74x compression!)
- BATCH_SIZE was set to 500, but would exceed 65KB limit

**Fix:** Two optimizations in v0.6.5:
1. Increased gossipsub `max_transmit_size`: 65KB → **10MB**
2. Dynamic BATCH_SIZE calculation: 500 blocks → **24,903 blocks**

### File 2: `crates/q-api-server/src/main.rs:1764`
```rust
// BEFORE:
const BATCH_SIZE: u64 = 500; // Fixed size

// AFTER:
const BYTES_PER_BLOCK: usize = 400; // Conservative estimate
const MAX_MESSAGE_SIZE: usize = 10 * 1024 * 1024; // 10MB
const TARGET_UTILIZATION: f64 = 0.95; // 95% bandwidth
const BATCH_SIZE: u64 = ((MAX_MESSAGE_SIZE as f64 * TARGET_UTILIZATION)
                         / BYTES_PER_BLOCK as f64) as u64;
// Result: 24,903 blocks per batch
```
