## Problem Analysis

### The Stuck Node Syndrome

**Diagnostic Output**:
```json
{
  "current_height": 4810,
  "highest_network_height": 2748,
  "is_syncing": false,
  "blocks_behind": 0,
  "connected_peers": 4
}
```

**What This Means**:
- Node thinks it's at height 4810 (wrong fork)
- Network consensus is at 2748 (canonical fork)
- `blocks_behind: 0` means system thinks it's synchronized
- `is_syncing: false` means no sync will happen
- **Node is permanently stuck!**

### Why Existing Code Failed

**Old Logic** (`crates/q-api-server/src/main.rs` line 3169):
```rust
// ❌ BROKEN: Only triggers if network height is HIGHER
if target > local_height + 5 {
    turbo_sync.sync_to_height(target).await
}
```

**Problem**: When `target < local_height` (backward reorg), condition is false, no sync happens!

## Solution Architecture

### 1. Fork Detector Module (`crates/q-storage/src/fork_detector.rs`)

**New Components**:

#### ForkEvent Enum - 4 Fork Types
```rust
pub enum ForkEvent {
    BackwardReorg {
        our_height: u64,
        network_height: u64,
        reorg_depth: u64,
    },
    MinorityFork {
        our_height: u64,
        majority_height: u64,
        peer_count_majority: usize,
        peer_count_our_fork: usize,
    },
    ForwardSync {
        our_height: u64,
        network_height: u64,
    },
    AheadOfNetwork {
        our_height: u64,
        network_height: u64,
    },
}
```

#### ForkDetector Struct
```rust
pub struct ForkDetector {
    peer_heights: Arc<tokio::sync::RwLock<HashMap<String, PeerHeightInfo>>>,
    min_peers_for_consensus: usize,      // 3 peers required
    consensus_threshold: f64,             // 67% must agree
    max_auto_reorg_depth: u64,           // 1000 blocks max
}
```

**Key Features**:
- **Peer Consensus Voting**: Requires 67% of peers to agree
- **Minimum Peer Count**: Needs at least 3 peers for fork detection
- **Stale Peer Cleanup**: Removes peers not updated in 60 seconds
- **Height Distribution Analysis**: Finds which height most peers agree on

### 2. Fork Detection Algorithm

**Step 1: Build Height Distribution**
```rust
let mut height_counts: HashMap<u64, usize> = HashMap::new();
for info in peers.values() {
    *height_counts.entry(info.height).or_insert(0) += 1;
}
```

**Step 2: Find Consensus Height**
```rust
let (consensus_height, peer_count) = height_counts
    .iter()
    .max_by_key(|(_, count)| *count)
    .map(|(h, c)| (*h, *c))
    .unwrap_or((our_height, 0));

let consensus_ratio = peer_count as f64 / peers.len() as f64;
```

**Step 3: Detect Fork Type**

| Condition | Fork Type | Action |
|-----------|-----------|--------|
| `consensus_height < our_height && consensus_ratio >= 67%` | **Backward Reorg** | Trigger automatic reorg |
| `consensus_height != our_height && consensus_ratio >= 67%` | **Minority Fork** | Warn user |
| `our_height > consensus_height + 10` | **Ahead of Network** | Warn isolated |
| `consensus_height > our_height` | **Forward Sync** | Normal operation |

## Automatic Reorg Resolution

### Safety Limits

**Safe Auto-Reorg**: Up to 1,000 blocks
- Automatically triggers Turbo Sync to network consensus
- Updates atomic height tracker
- Logs detailed reorg information

**Manual Intervention Required**: > 1,000 blocks
```
⚠️  [FORK DETECTOR] Reorg depth 2,062 exceeds safe limit (1000 blocks)
   MANUAL INTERVENTION REQUIRED!
   Run: ./fix_stuck_at_4810.sh
```

### Automatic Resolution Flow

```
1. Fork Detection (every 30 seconds)
   ↓
2. Detect BackwardReorg (our: 4810, consensus: 2748)
   ↓
3. Check safety (2062 > 1000? → Manual intervention)
   ↓
4. If safe: Trigger Turbo Sync
   ↓
5. turbo_sync.sync_to_height(2748)
   ↓
6. Update current_height_atomic to 2748
   ↓
7. Node continues from canonical fork
```

#[tokio::test]
async fn test_backward_reorg_detection() {
    let detector = ForkDetector::new();

    // 5 peers all at height 2748
    for i in 0..5 {
        detector.update_peer_height(format!("peer{}", i), 2748).await;
    }

    // Our node at 4810
    let event = detector.detect_fork(4810).await.unwrap();

    match event {
        ForkEvent::BackwardReorg { our_height, network_height, reorg_depth } => {
            assert_eq!(our_height, 4810);
            assert_eq!(network_height, 2748);
            assert_eq!(reorg_depth, 2062);
        }

    }
}

## Known Limitations

1. **Minimum 3 Peers Required**
   - Fork detection disabled if < 3 peers
   - Fallback to existing sync logic
   - **Mitigation**: Bootstrap node always available

2. **67% Consensus Threshold**
   - If network is 50/50 split, no action taken
   - Requires clear majority for safety
   - **Mitigation**: Typical blockchain forks resolve quickly

3. **1000 Block Auto-Reorg Limit**
   - Deep reorgs require manual intervention
   - Safety measure to prevent data loss
   - **Mitigation**: Automated diagnostic + fix scripts

4. **30-Second Detection Interval**
   - Not instant fork detection
   - Max 30 second delay before detection
   - **Mitigation**: Acceptable for blockchain use case
