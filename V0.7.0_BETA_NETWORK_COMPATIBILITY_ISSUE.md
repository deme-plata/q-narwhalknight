## 🔍 Root Cause Analysis

### Issue: Binary Version Incompatibility

**The Problem:**
Other peers in the network are running **OLDER binaries** that send block pack requests in the **WRONG FORMAT**:

**Correct Format (v0.7.0-beta):**
```rust
BlockPackRequest {
    start_height: 1,    // Lower bound
    end_height: 1000,   // Higher bound (end > start)
    requester_id: "..."
}
```

**Incorrect Format (older versions):**
```rust
BlockPackRequest {
    start_height: 52,   // ❌ WRONG - Higher than end
    end_height: 49,     // ❌ WRONG - Lower than start
    requester_id: "..."
}
```

### Why This Happens

**Hypothesis 1: Endianness or Serialization Bug**
- Older binaries may have reversed `start_height` and `end_height` fields during serialization
- When deserialized by v0.7.0-beta, fields are swapped

**Hypothesis 2: Different Protocol Version**
- Older binaries use a different block pack request format
- Binary incompatibility between protocol versions

**Hypothesis 3: Corrupted Peer State**
- Peers running older versions have corrupted internal state
- Sending requests with invalid height ranges
