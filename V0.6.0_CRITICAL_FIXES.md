# v0.6.0-beta Critical Fixes

**Date:** November 1, 2025
**Previous Version:** v0.5.32-beta
**New Version:** v0.6.0-beta

## Executive Summary

Security audit identified **26 CRITICAL issues**. This release addresses the top 8 most severe issues that could cause data loss or consensus failures.

## Critical Fixes Implemented

### 1. **SYNC-DOWN PROTECTION** (CRITICAL - Data Loss Prevention)

**Issue**: No protection against malicious peers announcing lower height
**Location**: `crates/q-api-server/src/main.rs:3063`
**Impact**: Could lose entire blockchain if peer announces height < current

**Fix**:
```rust
// BEFORE (v0.5.32):
if network_height > current_height + 5 {
    // Sync logic...
}

// AFTER (v0.6.0):
// 🚨 CRITICAL SAFETY: Prevent sync-down attacks
if network_height < current_height && current_height > 1000 {
    error!("🚨 CRITICAL: Sync-down attack detected!");
    error!("   Current height: {}, Network claims: {}", current_height, network_height);
    error!("   REFUSING to sync down - this would delete {} blocks!",
           current_height - network_height);
    continue; // Skip this sync attempt
}

if network_height > current_height + 5 {
    // Safe to sync UP only
}
```

### 2. **WAL CONFIGURATION CONFLICT** (CRITICAL - Data Persistence)

**Issue**: WAL size limit set twice with conflicting values (1024 then 0)
**Location**: `crates/q-storage/src/kv.rs:135-139`
**Impact**: Unclear WAL behavior, potential data loss on crash

**Fix**:
```rust
// BEFORE:
opts.set_wal_size_limit_mb(1024); // First setting
opts.set_wal_ttl_seconds(0);
opts.set_wal_size_limit_mb(0); // CONFLICT! Overwrites previous

// AFTER:
opts.set_wal_ttl_seconds(0); // Never delete WAL by time
opts.set_wal_size_limit_mb(0); // Unlimited WAL (let RocksDB manage)
opts.set_manual_wal_flush(false); // Auto-flush with set_sync(true)
```

### 3. **NETWORK ID VALIDATION** (CRITICAL - Cross-Network Contamination)

**Issue**: Blocks not validated for correct network_id on receipt
**Location**: `crates/q-api-server/src/main.rs` (block receipt handlers)
**Impact**: Testnet blocks could be accepted on mainnet

**Fix**: Add mandatory network ID check:
```rust
const EXPECTED_NETWORK_ID: &str = "testnet-phase2";

// In block receipt handler:
if block.header.network_id != EXPECTED_NETWORK_ID {
    warn!("🚫 REJECTED block {} - wrong network_id: {} (expected: {})",
          block.header.height, block.header.network_id, EXPECTED_NETWORK_ID);
    continue;
}
```

### 4. **BINARY SEARCH INFINITE LOOP** (HIGH - Node Hang)

**Issue**: Binary search in height detection could loop forever
**Location**: `crates/q-storage/src/lib.rs:632-656`
**Impact**: Node hangs during startup height detection

**Fix**: Add iteration limit:
```rust
let max_iterations = 64; // log2(2^64) = maximum possible iterations
let mut iterations = 0;

while low <= high && iterations < max_iterations {
    iterations += 1;
    let mid = (low + high) / 2;
    // ... rest of logic ...
}

if iterations >= max_iterations {
    warn!("⚠️ Binary search exceeded max iterations, using verified height: {}", verified);
}
```

### 5. **MEMORY EXHAUSTION IN RANGE QUERY** (HIGH - DoS)

**Issue**: No limit on get_qblocks_range, could request millions of blocks
**Location**: `crates/q-storage/src/lib.rs:543-577`
**Impact**: Attacker causes OOM by requesting huge ranges

**Fix**: Cap maximum blocks per request:
```rust
const MAX_BLOCKS_PER_REQUEST: usize = 1000;

pub async fn get_qblocks_range(&self, start_height: u64, mut limit: usize) -> Result<Vec<QBlock>> {
    // SAFETY: Prevent memory exhaustion
    limit = std::cmp::min(limit, MAX_BLOCKS_PER_REQUEST);

    if limit > MAX_BLOCKS_PER_REQUEST {
        warn!("⚠️ Block range request capped at {} (requested: {})",
              MAX_BLOCKS_PER_REQUEST, limit);
    }

    // ... rest of logic ...
}
```

### 6. **BLOCK VALIDATION - NETWORK ID CHECK** (HIGH)

**Issue**: BlockHeader::verify() doesn't check network_id matches expected
**Location**: `crates/q-types/src/block.rs:282-309`
**Impact**: Blocks from wrong network pass validation

**Fix**: Add network_id parameter:
```rust
pub fn verify(&self, expected_network_id: &str) -> Result<(), String> {
    // CRITICAL: Verify network ID matches
    if self.network_id != expected_network_id {
        return Err(format!(
            "Network ID mismatch: block has '{}', expected '{}'",
            self.network_id, expected_network_id
        ));
    }

    // ... existing verification checks ...
}
```

### 7. **FLOAT SANITIZATION ERROR HIDING** (MEDIUM)

**Issue**: NaN/Infinity silently converted to 0.0, hiding bugs
**Location**: `crates/q-api-server/src/block_producer.rs:464-472`
**Impact**: Invalid quantum calculations propagate through network

**Fix**: Return error instead of hiding:
```rust
fn sanitize_f64(value: f64, field_name: &str) -> Result<f64> {
    if value.is_nan() {
        return Err(anyhow::anyhow!("{} is NaN", field_name));
    }
    if value.is_infinite() {
        return Err(anyhow::anyhow!("{} is infinite", field_name));
    }
    Ok(value)
}
```

### 8. **VERSION BUMP IN CARGO.TOML**

Updated all package versions from `0.5.32-beta` to `0.6.0-beta`

## Deployment Instructions

1. Build new binary:
   ```bash
   timeout 36000 cargo build --release --package q-api-server
   ```

2. Stop service:
   ```bash
   systemctl stop q-api-server
   ```

3. Deploy binary:
   ```bash
   cp target/release/q-api-server gui/quantum-wallet/dist-final/downloads/q-api-server-v0.6.0-beta
   cp target/release/q-api-server gui/quantum-wallet/dist-final/downloads/q-api-server-linux-x86_64
   ```

4. Start service:
   ```bash
   systemctl start q-api-server
   ```

5. Monitor for sync-down attempts:
   ```bash
   journalctl -u q-api-server -f | grep "CRITICAL.*sync-down"
   ```
