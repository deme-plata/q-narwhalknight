# v0.0.5.1-beta - Peer Count Display Fix
## Resolves "Network Status: ❌ Isolated" Issue

**Release Date**: October 22, 2025
**Type**: Bug fix release
**Priority**: Medium (UX improvement)

---

## 🐛 Issue Fixed

**Problem**: Nodes always displayed "Network Status: ❌ Isolated" with `connected_peers: 0`, even when peers were being discovered and connected via mDNS.

**Root Cause**: The `connected_peers` field was **hardcoded to 0** during initialization and never updated with actual peer counts from the libp2p network manager.

---

## ✅ Changes Made

### 1. Added `get_peer_count()` Method to UnifiedNetworkManager

**File**: `crates/q-network/src/unified_network_manager.rs`
**Location**: Line 467-470 (after `get_discovered_peers()`)

```rust
/// Get the number of discovered/connected peers
pub async fn get_peer_count(&self) -> usize {
    self.discovered_peers.read().await.len()
}
```

**Purpose**: Provides a clean API to query the actual number of discovered/connected peers from the libp2p network manager.

---

### 2. Updated Node Status Handler to Use Real Peer Count

**File**: `crates/q-api-server/src/handlers.rs`
**Location**: Lines 35-41 (beginning of `node_status()` function)

```rust
let mut status = state.node_status.read().await.clone();

// Get actual peer count from libp2p manager (fixes hardcoded 0 issue)
if let Some(ref libp2p_manager) = state.libp2p_discovery {
    let peer_count = libp2p_manager.lock().await.get_peer_count().await;
    status.connected_peers = peer_count;
}
```

**Purpose**: Queries the libp2p manager for the current peer count and updates the node status before returning it to the API client.

**Behavior**:
- If `libp2p_discovery` is available → returns actual peer count
- If `libp2p_discovery` is None → returns 0 (fallback)

## ⚠️ Known Limitations

### 1. mDNS Discovers All libp2p Applications

**Issue**: mDNS will discover ANY libp2p application on the local network, not just Q-NarwhalKnight nodes.

**Observed**: Nodes discovered "nova-chat" peers (file sharing app) which then immediately disconnected due to protocol mismatch.

**Impact**: `discovered_peers` count may temporarily include incompatible applications, but these connections close quickly so the count self-corrects.

**Future Fix**: Add gossipsub topic filtering to only count peers subscribed to Q-NarwhalKnight topics (`/qnk/*`).

### 2. Single Node Will Always Show 0 Peers

**Expected Behavior**: If you run a single Q-NarwhalKnight node with no other nodes on the network, it will correctly show `connected_peers: 0`.

**Not a Bug**: This is correct behavior - there are no other Q-NarwhalKnight nodes to connect to.

**Solution**: Run multiple nodes or connect to a bootstrap network.

## 🎯 Performance Impact

**Minimal**: The `get_peer_count()` method:
- Acquires read lock on `discovered_peers` HashSet
- Returns HashSet length (O(1) operation)
- Releases lock immediately

**Estimated overhead**: <0.1ms per status request

**TPS Impact**: None - peer count query happens outside the transaction processing pipeline
