## 🎯 **OBJECTIVE**

Implement KV-cache coordination across distributed pipeline to eliminate redundant computation during autoregressive token generation.

**Problem**: Current implementation re-processes entire prompt every token:
- Token 1: 10 tokens (0.5s)
- Token 100: 110 tokens (5.5s) → 11× slower
- **Total**: 275 seconds for 100 tokens

**Solution**: Cache key/value tensors from attention layers, only process NEW token:
- Token 1: 10 tokens (0.5s) - cache miss
- Token 2-100: 1 token each (0.5s) - cache hit
- **Total**: 50 seconds for 100 tokens → **14× FASTER**

## 🔧 **PHASE 2: REMAINING WORK**

### **Task 1: Expose KV-Cache from MistralLayer** ⭐ **CRITICAL**

**File**: `crates/q-ai-inference/src/mistral_model.rs`

**Current Situation**: `MistralLayer::forward()` computes key/value tensors in attention but doesn't return them.

**Required Changes**:
```rust
// Add method to MistralLayer:
pub fn forward_with_cache(
    &self,
    x: &Tensor,
    attention_mask: Option<&Tensor>,
    position_ids: &Tensor,
    kv_cache: Option<(Tensor, Tensor)>,  // Previous cache
) -> Result<(Tensor, Tensor, Tensor)> {  // (output, new_key, new_value)
    // Existing forward logic
    let hidden = self.forward(x, attention_mask, position_ids)?;

    // Extract key/value from attention layer
    let (new_key, new_value) = self.self_attn.get_kv_cache()?;

    // Concatenate with previous cache if present
    let updated_key = if let Some((prev_key, _)) = kv_cache {
        Tensor::cat(&[&prev_key, &new_key], 2)?  // Concat on seq_len dimension
    } else {
        new_key
    };

    let updated_value = if let Some((_, prev_value)) = kv_cache {
        Tensor::cat(&[&prev_value, &new_value], 2)?
    } else {
        new_value
    };

    Ok((hidden, updated_key, updated_value))
}
```

**Impact**: Enables actual KV-cache reuse across tokens.

### **Task 2: Update Worker to Use execute_layers_with_cache()** ⭐

**File**: `crates/q-network/src/distributed_ai_worker.rs`

**Current**: Uses `engine.execute_layers()` (no cache)

**Required Changes**:
```rust
async fn run_model_layers(
    &self,
    input_tensor: TensorData,
    start_layer: usize,
    end_layer: usize,
) -> Result<TensorData> {
    let engine = self.engine.read().await.as_ref().ok_or(...)?;

    // Extract KV-cache from input tensor
    let kv_cache = input_tensor.extract_kv_cache();

    let seq_len = input_tensor.shape[1];
    let position_ids: Vec<u32> = (0..seq_len as u32).collect();

    // NEW: Use execute_layers_with_cache() instead of execute_layers()
    let (output_data, output_shape, new_kv_cache) = engine.execute_layers_with_cache(
        input_tensor.data,
        input_tensor.shape,
        position_ids,
        kv_cache,
    ).await?;

    // Include updated cache in output
    let mut output_tensor = TensorData::new(output_data, output_shape);
    if let Some((key, value, shape)) = new_kv_cache {
        output_tensor.set_kv_cache(key, value, shape);
    }

    Ok(output_tensor)
}
```

**Impact**: Workers now forward KV-cache between nodes.

### **Task 3: Update Coordinator Autoregressive Loop** ⭐

**File**: `crates/q-network/src/distributed_ai_coordinator.rs`

**Current**: Sends full prompt every token

**Required Changes**:
```rust
pub async fn generate_distributed_autoregressive(...) -> Result<...> {
    let mut kv_cache_state: Option<TensorData> = None;  // Track cache

    for token_idx in 0..max_tokens {
        // CHANGE 1: Only send NEW token (not full prompt)
        let input = if token_idx == 0 {
            initial_prompt.to_string()  // First token: full prompt
        } else {
            // Subsequent tokens: only last generated token
            generated_text.chars().last().unwrap().to_string()
        };

        // CHANGE 2: Include KV-cache in request
        self.publish_inference_request_with_cache(
            format!("{}-token-{}", request_id, token_idx),
            &input,
            kv_cache_state.clone(),  // Send cache from previous token
        ).await?;

        // Wait for response with updated cache
        let (token, updated_cache) = self.wait_for_token_with_cache(
            format!("{}-token-{}", request_id, token_idx),
        ).await?;

        // CHANGE 3: Update cache state
        kv_cache_state = updated_cache;

        generated_text.push_str(&token);

        // Check for EOS
        if token == "</s>" || token == "<|endoftext|>" {
            break;
        }
    }

    Ok((generated_text, nodes_used))
}
```

**Impact**: Only processes 1 new token per iteration (instead of entire sequence).

## 🚨 **DESIGN CONSIDERATIONS**

### **Cache Invalidation**:
- **Problem**: What happens when user sends new prompt?
- **Solution**: Coordinator resets `kv_cache_state = None` on new request
- **Implementation**: Check `request_id` change → invalidate cache

### **Cache Size Management**:
- **Problem**: Cache grows linearly with sequence length
- **Solution**: Set `max_seq_len` (e.g., 2048 tokens max)
- **Implementation**: Truncate oldest cache entries when limit reached

### **Cross-Node Cache Coordination**:
- **Problem**: Each node has different layers → different cache
- **Solution**: Each node's cache is layer-specific, forwarded with tensors
- **Implementation**: Node 1 cache → Node 2 → Node 3 → Node 4 (accumulated)

### **Cache Compression**:
- **Problem**: 26.2 MB cache for 100 tokens is large
- **Solution**: Combine with zstd compression (Phase 2 optimization)
- **Expected**: 4× compression → 6.5 MB total cache
