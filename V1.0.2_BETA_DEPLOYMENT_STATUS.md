---

## 🔍 Implementation Details

### Layer 1: Timeout Wrapper with Exponential Backoff
**File**: `crates/q-api-server/src/main.rs` (lines 4272-4346)
**What**: Adds 5-second timeout to `save_qblock()` with 3 retry attempts
**Why**: Prevents infinite hang when RocksDB writes stall
**Impact**: Max 15 seconds per block (3 × 5s), then graceful degradation

### Layer 2: spawn_blocking for RocksDB Writes
**File**: `crates/q-storage/src/kv.rs` (lines 1031-1065)
**What**: Wraps `write_batch_internal()` in `tokio::task::spawn_blocking`
**Why**: Prevents Tokio executor thread starvation
**Impact**: RocksDB blocking I/O never blocks async tasks

### Layer 3: Bounded Mining Channel
**File**: `crates/q-api-server/src/main.rs` (line 1934)
**What**: Replaces `unbounded_channel()` with `channel(10_000)`
**Why**: Prevents memory exhaustion from unbounded queue growth
**Impact**: Backpressure at 10,000 submissions (~40 seconds worth)
