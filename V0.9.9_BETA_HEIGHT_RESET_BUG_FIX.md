# v0.9.9-beta: Critical Height Reset Bug Fix

## Executive Summary

**Fixed catastrophic height reset bug** where blockchain height resets to 0 after service restart, causing nodes to start producing blocks from genesis while network is thousands of blocks ahead.

**Impact**:
- Node falls out of consensus
- Creates massive desync (local height 1-8, network height 2793-2795)
- Prevents proper network participation
- **Severity**: CRITICAL - affects ALL nodes on restart

**Root Cause**: Storage layer's `get_highest_contiguous_block()` probe heights missed the actual block range (2000-3000), returning height=0 despite database containing 2793 blocks.

**Fix**: Comprehensive probe height coverage including missing ranges (2000, 1500, 1000, 3000, 5000, etc.)

## Long-Term Prevention

### Database Pointer Integrity

**Priority**: Implement `qblock:latest` pointer persistence to avoid fallback scanning:

```rust
// On every block store:
self.hot_db.put(CF_BLOCKS, b"qblock:latest", &height.to_be_bytes()).await?;

// On every block deletion (pruning):
let new_latest = self.get_highest_contiguous_block().await?;
self.hot_db.put(CF_BLOCKS, b"qblock:latest", &new_latest.to_be_bytes()).await?;
```

**Benefits**:
- Instant height recovery (no scanning)
- O(1) complexity vs O(log n) binary search
- Eliminates probe height dependency
- More reliable in edge cases

### Monitoring & Alerts

**Critical Metrics**:
1. `blockchain_height_monotonic` - MUST ONLY INCREASE
