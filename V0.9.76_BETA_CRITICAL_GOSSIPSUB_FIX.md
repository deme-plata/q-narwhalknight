# v0.9.76-beta: Critical Gossipsub Auto-Trigger Fix

## Release Date
2025-11-09

## Critical Bug Fixed

### The Real Problem: Competing Sync Paths

v0.9.75-beta added optimistic peer testing for direct P2P BlockPackCodec sync, but it was **NEVER BEING USED** because an old gossipsub auto-trigger was intercepting all sync requests first!

### Root Cause

**Two sync paths existed in the code**:

1. **OLD PATH (line 3163-3244)**: Gossipsub broadcast auto-trigger
   - Runs in peer height announcement handler
   - Triggers immediately when higher peer discovered
   - Uses slow gossipsub broadcast (unreliable, slow)
   - **ALWAYS ran FIRST**, preventing new path from activating

2. **NEW PATH (line 5000-5150)**: Direct P2P BlockPackCodec (v0.9.75-beta)
   - Uses optimistic peer testing
   - Direct peer-to-peer request-response
   - Fast, reliable, 2000 blocks per request
   - **NEVER ran** because old path intercepted first!

### Evidence from Server Alpha Logs

```
✅ v0.9.75-beta features present: "optimistic peer testing"
❌ But using OLD gossipsub path: "📤 [TURBO SYNC] Sent gossipsub request for blocks 5461-9126"
❌ NOT using NEW P2P path: No "📥 [FAST SYNC #1] Requesting X blocks from peer"
```

**Result**: Despite having v0.9.75-beta code, nodes were still using the slow gossipsub broadcast method!

## The Fix (v0.9.76-beta)

**Disabled the old gossipsub auto-trigger** at line 3176:

```rust
// BEFORE (v0.9.75-beta and earlier):
if target > local_height + 5 {
    // Send gossipsub requests (slow broadcast)
    tokio::spawn(async move {
        // ... gossipsub code ...
    });
}

// AFTER (v0.9.76-beta):
if false { // DISABLED - replaced by optimistic P2P sync at line 5000+
    // OLD CODE DISABLED
}
```

**Why this works**:
- Old gossipsub auto-trigger no longer intercepts
- New optimistic P2P sync loop can now run
- Direct peer-to-peer BlockPackCodec requests are sent
- 200x performance improvement can actually be realized!

## Why v0.9.75-beta Didn't Work

v0.9.75-beta **added the optimistic peer testing code** but didn't realize the old gossipsub auto-trigger was intercepting ALL sync requests BEFORE the new code could run!

**The sequence in v0.9.75-beta was**:
1. Peer height announcement received → Line 3154
2. Network height updated → Line 3161
3. **OLD gossipsub auto-trigger fires** → Line 3177 (if target > local_height + 5)

5. **NEW P2P sync never runs** → Line 5000+ never reached!

**The sequence in v0.9.76-beta is**:

3. **OLD trigger disabled** → Line 3176 (if false)
4. Sync loop continues → Line 5000+
5. **NEW P2P sync runs!** → Lines 5019-5150 with optimistic peer testing

## Technical Details

### Why Gossipsub is Slow

**Gossipsub broadcast**:
- Sends request to TOPIC (not specific peer)
- Any peer can respond (or none!)
- No delivery guarantee
- Subject to "InsufficientPeers" errors
- Must wait for broadcast + response propagation
- Single-threaded (one request at a time)

**BlockPackCodec P2P**:
- Sends request to SPECIFIC peer
- Direct peer-to-peer connection
- Delivery guaranteed (or timeout + retry)
- No gossipsub dependency
- Parallel requests (3 simultaneous)
- 2000 blocks per request

### Why The Old Trigger Wasn't Removed Earlier

The old gossipsub auto-trigger (line 3163-3244) was added in v0.8.6-beta as a "missing piece" for automatic sync. It worked, but was slow.

v0.9.68-beta added BlockPackCodec (the fast P2P protocol).

v0.9.75-beta added optimistic peer testing for BlockPackCodec.

But **no one realized** the old auto-trigger was still running and intercepting all sync requests!

v0.9.76-beta finally disables the old trigger, allowing the new P2P sync to work as designed.
