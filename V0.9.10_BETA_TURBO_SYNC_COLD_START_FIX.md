## 🎯 THE PROBLEM: Circular Dependency

New nodes joining the network at height 0 get stuck in a circular dependency and never sync.

### The Vicious Circle

```
┌─────────────────────────────────────────────────┐
│ 1. New node starts at height 0                 │
│    ↓                                            │
│ 2. Skips peer height announcement               │
│    (Line 2994: "No blocks yet, skipping")      │
│    ↓                                            │
│ 3. Network doesn't know about this peer         │
│    ↓                                            │
│ 4. Turbo sync peer registry remains empty       │
│    ↓                                            │
│ 5. Node never receives peer height announcements│
│    ↓                                            │
│ 6. Network height stays at 0                    │
│    ↓                                            │
│ 7. Sync condition not met (network_height == 0) │
│    ↓                                            │
│ 8. Node thinks it's "synced" (line 3583)       │
│    ↓                                            │
│ 9. Block production paused (behind network)     │
│    ↓                                            │
│ 10. STUCK FOREVER - never syncs! ❌             │
└─────────────────────────────────────────────────┘
```

## 🔍 Evidence from Code

### Problem 1: Nodes at Height 0 Don't Announce Themselves

```rust
match storage_clone.get_highest_contiguous_block().await {
    Ok(height) => {

```

**Why this is wrong**:
- New nodes need to announce themselves so they can RECEIVE peer height announcements
- Without announcing, the network doesn't send them updates
- They stay isolated and never learn about other peers

### Problem 2: Sync Condition Requires network_height > 0

**File**: `crates/q-api-server/src/main.rs:3877-3879`

```rust
else if network_height > current_height + 5 {
    let blocks_behind = network_height - current_height;
    // ... start sync ...
```

**Why this fails**:
- If node never receives peer announcements, `network_height` stays at 0
- Condition `network_height > current_height + 5` = `0 > 0 + 5` = **FALSE**
- Sync never triggers!

### Problem 3: Node Thinks It's Synced When network_height == 0

**File**: `crates/q-api-server/src/main.rs:3583`

```rust
let is_synced = network_height == 0 || (network_height > 0 && current_height + sync_threshold >= network_height);
```

**Why this is wrong**:
- New node at height 0 with `network_height == 0` evaluates to `is_synced = true`
- But the node is actually NOT synced - it just hasn't learned about the network yet!
- This prevents sync from being attempted

## ✅ THE SOLUTION: Multi-Layer Fix

We need THREE fixes to break the circular dependency:

### Fix 1: Allow Height 0 Announcements (Bootstrap Discovery)

**File**: `crates/q-api-server/src/main.rs:2994-2995`

**Change**:
```rust
match storage_clone.get_highest_contiguous_block().await {
    Ok(height) => {
        // ✅ v0.9.10-beta FIX: Allow height 0 announcements for bootstrap discovery
        // New nodes MUST announce themselves to receive peer updates
        if height == 0 {
            info!("📡 [COLD START] Announcing to network for bootstrap discovery (height 0)");
        }

        // Get our peer ID
        let peer_id = {
            let info = peer_info_clone.read().await;
            info.0.clone()
        };

        // Announce to network (even at height 0!)
        #[derive(serde::Serialize, serde::Deserialize)]
        struct PeerHeightAnnouncement {
            peer_id: String,
            highest_block: u64,
        }

        let announcement = PeerHeightAnnouncement {
            peer_id: peer_id.clone(),
            highest_block: height,  // OK to send 0
        };
```
