### Evidence from Logs:

1. **Block Producer Watchdog Triggered**:
   - Height stuck at 319 for 60+ seconds
   - No new blocks being produced
   - No panic or crash - silent stall

2. **No Panics Detected**:
   - No thread panics in logs
   - No fatal errors
   - Clean shutdown on restart

3. **Likely Causes**:
   - **Block producer task deadlock** - Most likely

---

## 💡 HYPOTHESIS

**Primary Hypothesis**: TurboSync batch send caused block producer deadlock

**Mechanism**:
1. Peer requested large batch (319 blocks)
2. TurboSync loaded and serialized 319 blocks
3. Heavy I/O operation may have blocked block producer task
4. Block producer unable to acquire database lock or tokio runtime stalled

**Supporting Evidence**:
- Stall occurred immediately after batch send
- No other significant events in logs
- Database still responsive (height queries working)
- Suggests task scheduling issue, not database corruption

- Command: `systemctl restart q-api-server`
- Result: Service restarted successfully
- Verification: Phase 5 network reconnected

**Expected Outcome**:

- No data loss (blockchain intact up to height 319)

## 🛠️ RECOMMENDED FIXES

### Short-term (Apply Now):
1. **Monitor watchdog alerts** - Automatic restart may be needed
2. **Limit TurboSync batch sizes** - Cap at 100 blocks per batch
3. **Increase block producer timeout** - From 60s to 120s

### Medium-term (v0.9.26):
1. **Add TurboSync batch size limits**:
   ```rust
   const MAX_BATCH_SIZE: u64 = 100; // Prevent large batch stalls

   if end_height - start_height > MAX_BATCH_SIZE {
       end_height = start_height + MAX_BATCH_SIZE;
   }
   ```

2. **Spawn TurboSync on separate task**:
   ```rust
   // Don't block block producer
   tokio::spawn(async move {
       turbo_sync.send_batch(peer, blocks).await
   });
   ```

3. **Add block producer health monitoring**:
   ```rust
   // Publish health metrics every 10 seconds
   metrics::gauge!("block_producer.last_block_time", last_block_time);
   ```

### Long-term (v0.10.0):
1. **Separate tokio runtimes** - Isolate block producer from sync
2. **Non-blocking database** - Use connection pool
3. **Async tracing** - Identify blocking operations
4. **Auto-recovery** - Restart block producer task on stall
