# v0.9.66-beta - Bincode Serialization Discovery and Fix

**Date:** 2025-11-08 23:10 CET
**Issue:** Docker containers use bincode, not postcard/MessagePack
**Root Cause:** Docker binary uses bincode::serialize for turbo sync requests
**Priority:** CRITICAL (blocks decentralized P2P sync)

---

## 🔍 ROOT CAUSE DISCOVERED

### The Real Problem:

Docker containers are sending turbo sync requests using **bincode** serialization, not postcard!

**Evidence from logs:**
```
Received bytes: [82, fe, be, c8, 06, 34, 31, 32, 44, 33, 4b, 6f, 6f...]
                 ^^  ^^  ^^  ^^  ^^  ^^ASCII: "412D3KooW..." (PeerId)
```

- First byte `0x82` = bincode varint encoding
- Bytes `0xfe, 0xbe, 0xc8, 0x06` = bincode-encoded integers
- Starting at byte 5: ASCII PeerId string `"412D3KooW..."`

### Why This Happened:

1. **Different compilation**: Docker container built with different serialization defaults
2. **Workspace dependency**: `bincode` is already a workspace dependency
3. **Code divergence**: Some binary used `bincode::serialize()` instead of `postcard::to_allocvec()`

---

## ✅ THE FIX

### Changes Made:

**File:** `crates/q-storage/src/turbo_sync.rs` (lines 310-350)

Added bincode fallback to cascading decode:
```rust
// ✅ v0.9.66-beta: Try bincode NEW format (Docker containers use bincode!)
tracing::info!("🔍 [TURBO SYNC DEBUG] Trying bincode format");
match bincode::deserialize::<Self>(data) {
    Ok(req) => {
        tracing::info!("✅ [TURBO SYNC DEBUG] Bincode NEW format decoded successfully!");
        req.validate_heights()?;
        return Ok(req);
    }
    Err(e3) => {
        tracing::warn!("⚠️ Bincode NEW format decode failed: {:?}", e3);
    }
}

// ✅ v0.9.66-beta: Try bincode OLD format (without protocol_version)
match bincode::deserialize::<OldBlockPackRequest>(data) {
    Ok(old) => {
        tracing::info!("✅ [TURBO SYNC DEBUG] Bincode OLD format decoded successfully!");
        let req = Self {
            protocol_version: 0,
            start_height: old.start_height,
            end_height: old.end_height,
            request_id: old.request_id,
        };
        req.validate_heights()?;
        Ok(req)
    }
    Err(e4) => {
        // All 6 formats failed
        tracing::error!("❌ ALL decode attempts failed!");
        anyhow::bail!("Failed to decode BlockPackRequest...")
    }
}
```

### Complete Cascading Decode Strategy:

1. **Postcard NEW** (protocol_version=1)
2. **Postcard OLD** (no protocol_version)
3. **MessagePack NEW** (cross-format compat)
4. **MessagePack OLD** (no protocol_version)
5. **Bincode NEW** ← Docker containers! ✅
6. **Bincode OLD** ← Fallback for old Docker builds

## 📝 LESSONS LEARNED

### Why Bincode Instead of Postcard?

The Docker container binary was compiled with a different code path that uses:
- `bincode::serialize()` instead of `postcard::to_allocvec()`

This happened because:
1. Multiple serialization libraries in dependencies
2. Code evolved over time with different defaults
3. No strict enforcement of single serialization format

### Prevention for Future:

1. **Standardize serialization**: Use only postcard for P2P messages
2. **Add protocol tests**: Test cross-version compatibility
3. **Version negotiation**: Implement protocol version handshake
4. **CI/CD checks**: Verify serialization format consistency
