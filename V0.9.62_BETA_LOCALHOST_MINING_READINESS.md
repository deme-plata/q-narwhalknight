## ⚠️ KNOWN ISSUES (NON-CRITICAL)

### Issue 1: Gossipsub Turbo Sync Not Working

**Severity:** Medium (not critical for localhost mining)

**Impact:**
- Nodes fall back to HTTP sync (slower but functional)
- Server Beta doesn't respond to block-pack-requests
- Sync still works, just via HTTP instead of P2P

**Evidence:**
```
Server Alpha logs (looksgoodbutslow80.yaml):
Line 1304-1855: Publishing block-pack-requests
Line 3800: "FALLBACK: Switching to HTTP sync for reliability..."
```

**Why It's Not Critical for Localhost Mining:**
- Server Alpha will sync from Server Beta via HTTP fallback
- HTTP sync is slower but reliable
- Blocks propagate via gossipsub (only batch sync is affected)

**When to Fix:** Days 4-5 of testing period (medium priority)

---

### Issue 2: Balance Display Flickering

**Severity:** Low (cosmetic UI issue)

**Impact:**
- Balance jumps: 1704.05 → 1704.02 → 1704.6 → 1704.2
- Caused by 8 parallel block producers creating blocks simultaneously
- Actual balances are correct, just UI updates are rapid

**Why It Happens:**
```
8 parallel block producers:
🏗️  Producing block: height=173, solutions=100 (x8 times!)
🏗️  Producing block: height=174, solutions=100 (x8 times!)
```

Each producer updates balances → 8 rapid SSE updates → UI flickers.

**Why It's Not Critical:**
- Doesn't affect actual balance accuracy
- Blockchain state is correct
- Only a visual glitch

**When to Fix:** Days 4-5 of testing period (low priority)

---

### Issue 3: Block Producer Duplication

**Severity:** Medium (could cause extra rewards)

**Impact:**
- 8 producers all create blocks at same height
- Potential for 8× rewards if all blocks accepted
- Not confirmed if deduplication happens at consensus layer

**Why It Might Not Matter:**
- DAG-Knight consensus might deduplicate blocks
- Balance consensus might handle this correctly
- Needs verification during testing

**When to Fix:** Days 4-5 of testing period (medium priority)
