## 🚨 Critical Security & Stability Release

This release addresses **8 CRITICAL security vulnerabilities** identified in comprehensive security audit. All fixes have been implemented and tested.

---

## 🔐 Critical Fixes Implemented

### 1. **Sync-Down Attack Prevention** (CRITICAL)
**Issue:** Malicious peers could announce lower blockchain height, causing node to delete all blocks
**Impact:** Total data loss, billions of dollars lost on mainnet
**Fix:** Added explicit sync-down protection with loud error logging
**Location:** `crates/q-api-server/src/main.rs:3061-3070`

```rust
if network_height < current_height && current_height > 1000 {
    error!("🚨 CRITICAL: Sync-down attack detected!");
    error!("   REFUSING to sync down - this would delete {} blocks!",
           current_height - network_height);
    continue; // DO NOT sync down!
}
```

### 2. **WAL Configuration Conflict** (CRITICAL)
**Issue:** Write-Ahead Log size limit set twice (1024MB then 0), causing unclear durability behavior
**Impact:** Data loss on crash/power failure
**Fix:** Removed conflicting setting, clarified WAL configuration
**Location:** `crates/q-storage/src/kv.rs:135-139`

### 3. **Network ID Validation (Batch Sync)** (CRITICAL)
**Issue:** Blocks from wrong networks (testnet-phase1, mainnet) could be accepted
**Impact:** Cross-network contamination, consensus failure
**Fix:** Validate all blocks have correct `network_id="testnet-phase2"`
**Location:** `crates/q-api-server/src/main.rs:1859-1868`

### 4. **Binary Search Infinite Loop** (HIGH)
**Issue:** Height detection binary search could loop forever on corrupted database
**Impact:** Node hangs on startup, requires manual intervention
**Fix:** Added 1000 iteration limit with safety abort
**Location:** `crates/q-storage/src/lib.rs:632-643`

### 5. **Memory Exhaustion DoS** (HIGH)
**Issue:** No limit on `get_qblocks_range()`, attacker could request millions of blocks
**Impact:** Out-of-memory crash, node unavailable
**Fix:** Capped requests to 1000 blocks maximum
**Location:** `crates/q-storage/src/lib.rs:543-551`

### 6. **Network ID Validation (Single Block)** (HIGH)
**Issue:** Single block sync path not validating network_id (batch sync was protected)
**Impact:** Cross-network contamination via fallback sync path
**Fix:** Added same network_id validation as batch sync
**Location:** `crates/q-api-server/src/main.rs:1941-1948`

### 7. **Float Calculation Bug Hiding** (MEDIUM)
**Issue:** NaN/Infinity silently converted to 0.0, hiding quantum calculation bugs
**Impact:** Invalid quantum metadata propagated through network
**Fix:** Return errors loudly instead of silent conversion
**Location:** `crates/q-api-server/src/block_producer.rs:466-474`

### 8. **Block Verification Network Check** (HIGH)
**Issue:** `BlockHeader::verify()` didn't check network_id at cryptographic level
**Impact:** Blocks from wrong networks could pass verification
**Fix:** Added mandatory network_id parameter to verify()
**Location:** `crates/q-types/src/block.rs:282-292`

## ⚠️ Breaking Changes

### API Changes
- `BlockHeader::verify()` now requires `expected_network_id: Option<&str>` parameter
- Existing callers should pass `Some("testnet-phase2")` for validation or `None` for legacy behavior

### P2P Changes
- Gossipsub topics now use `/qnk/testnet-phase2/*` instead of `/qnk/testnet/*`
- Nodes MUST be on same network_id to sync
- Phase 1 nodes (v0.5.31 and earlier) cannot sync with Phase 2 nodes

### Database Changes
- Blocks now require `network_id` and `phase` fields
- Old blocks from v0.5.31 or earlier cannot be loaded (incompatible schema)
- **Recommendation:** Start fresh database for Phase 2 (already done in v0.5.32)
