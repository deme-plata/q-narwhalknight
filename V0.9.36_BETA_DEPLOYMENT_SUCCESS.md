## Problem Fixed

**Previous Issue (v0.9.35-beta and earlier)**:
```
❌ [TURBO SYNC] Failed to publish block pack to topic /qnk/testnet-phase5/block-pack-responses: MessageTooLarge
✅ [TURBO SYNC P2P] Served pack with 84791.1 KB compressed (84MB exceeds 10MB limit!)
```

**Root Cause**:
- chunk_size: 5000 blocks created 84MB compressed packs
- gossipsub max_transmit_size: 10MB
- **Result**: TURBO SYNC completely broken, fallback to slow HTTP sync

**New Configuration (v0.9.36-beta)**:
- chunk_size: 500 blocks creates ~8-10MB compressed packs
- gossipsub max_transmit_size: 50MB (5x safety margin)
- **Result**: ✅ TURBO SYNC working perfectly via P2P

### Files Modified

**1. `crates/q-storage/src/turbo_sync.rs`**
- Line 76: `chunk_size: 5000` → `chunk_size: 500`
- Line 83: `chunk_timeout: 60s` → `chunk_timeout: 30s`

**2. `crates/q-network/src/unified_network_manager.rs`**
- Line 389: `max_transmit_size(10 * 1024 * 1024)` → `max_transmit_size(50 * 1024 * 1024)`

### Code Changes

**Chunk Size Reduction**:
```rust
impl Default for TurboSyncConfig {
    fn default() -> Self {
        Self {
            parallel_streams: 8,
            chunk_size: 500,  // 🔧 v0.9.36-beta: Reduced from 5000
            // 500 blocks × ~20KB/block ≈ 10MB (fits within 50MB limit)
            delta_compression: true,
            compression_level: 3,
            enable_pipelining: true,
            max_peer_connections: 16,
            chunk_timeout: Duration::from_secs(30),  // Back to 30s
            smart_protocol: true,
        }
    }
}
```

**Gossipsub Message Size Increase**:
```rust
// 🚀 v0.9.36-beta: Increased max_transmit_size to 50MB
// 50MB limit provides 5x safety margin for compression variance
let gossipsub_config = gossipsub::ConfigBuilder::default()
    .heartbeat_interval(Duration::from_millis(100))
    .validation_mode(ValidationMode::Strict)
```
