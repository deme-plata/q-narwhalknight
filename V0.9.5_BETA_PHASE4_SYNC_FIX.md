# v0.9.5-beta: Phase 4 Network Sync Fix

**Date**: 2025-11-05
**Version**: v0.9.5-beta
**Network**: testnet-phase4
**Issue**: Server Alpha stuck on phase3, cannot sync with Server Beta (phase4, 8600+ blocks)

---

## 🚨 Problem Identified

### Network Mismatch:
- **Server Beta (Bootstrap)**: testnet-phase4, 8600+ blocks ✅
- **Server Alpha (Docker)**: testnet-phase3, stuck at height 0-20 ❌

### Symptoms from Server Alpha Logs:

```log
# OLD (Nov 3): Node was on phase3
Publishing block pack response to /qnk/testnet-phase3/block-pack-responses

# NEW (Nov 5): Node upgraded to phase4 but using old binary
Publishing block 20 to gossipsub topic: /qnk/testnet-phase4/blocks
❌ Failed to publish block: InsufficientPeers

# Bootstrap Discovery Failing:
🔍 [BOOTSTRAP] Attempting HTTP discovery from http://185.182.185.227:8080...
⏳ Waiting for bootstrap discovery to complete...
(No peers discovered)

# Height Reset Loop:
⏸️  Block production paused: syncing 1306 blocks behind (current: 0, network: 1306)
```

**Root Cause**: Server Alpha running old v0.8.10-beta binary with phase3/phase4 mismatch, cannot connect to Server Beta's phase4 network.

---

## ✅ The Solution

### Build v0.9.5-beta with testnet-phase4

**Changes**:
1. Network ID: `testnet-phase4` (matches Server Beta)
2. Version: `v0.9.5-beta`
3. All latest fixes + DEX integration

**No Database Reset Needed**:
- Server Beta: Keep existing 8600+ phase4 blocks
- Server Alpha: Delete old phase3 database, sync from Server Beta

```bash

  -p 8080:8080 -p 9001:9001 \

  -e Q_DB_PATH=/data \
  --restart unless-stopped \
  debian:bookworm-slim \

docker logs q-v0.9.5-beta -f
```

**Expected**:
