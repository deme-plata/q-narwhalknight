## 🎯 Problem Fixed

**Root Cause**: Block producer hangs indefinitely on `save_qblock()` RocksDB write operations.

**Symptoms**:
- Block production stops
- Watchdog fires STALLED warnings every 60 seconds
- No error messages (silent hang)
- Mining submissions continue (unbounded channel)
- Network halts completely

**Trigger**: Perfect storm of:
1. High mining submission rate (247/sec observed)
2. RocksDB write latency spike
3. No timeout on async database operations
4. Unbounded channel allows infinite queue growth

---

## ✅ Solution Implemented

### Layer 1: Timeout + Exponential Backoff

**Location**: `crates/q-api-server/src/main.rs` line 4272

**Changes**:
- Added 5-second timeout to `save_qblock()` call
- Exponential backoff retry (3 attempts: 100ms, 200ms, 400ms)
- Graceful degradation (skip block, continue producing)
- Detailed logging for timeout events

**Code Pattern**:
```rust
use tokio::time::{timeout, Duration, sleep};

let max_retries = 3;
for attempt in 0..max_retries {
    match timeout(Duration::from_secs(5), save_qblock(&block)).await {
        Ok(Ok(())) => {
            // Success! Advance height and continue
            break;
        }
        Err(_timeout) if attempt < max_retries - 1 => {
            warn!("TIMEOUT: Retrying...");
            sleep(exponential_backoff).await;
            continue;
        }
        Err(_timeout) => {
            error!("CRITICAL TIMEOUT: Skipping block, continuing production");
            break; // Give up, try next block
        }
    }
}
```

**Why This Works**:
1. **Prevents infinite hangs** - Max 15 seconds per block (3 × 5s)
2. **Allows recovery** - Producer continues even if one block fails
3. **No network halt** - System degrades gracefully under load
4. **Maintains height consistency** - Only advances height after successful save
5. **Observable** - Clear log messages for monitoring
