## Real Root Cause: Bootstrap Peer Discovery Failure

### Issue 1: HTTP Bootstrap Discovery
**Location**: `crates/q-api-server/src/config.rs`

The bootstrap discovery tries to fetch peers from `http://185.182.185.227:8080/api/v1/status`, but:
- Docker containers may not have network route
- HTTP request may timeout or fail silently
- Peer ID extraction may fail

### Issue 2: mDNS-Only Discovery
**Current Behavior**: Server Alpha containers discover each other via mDNS (local network)
**Problem**: mDNS only works on the same physical/virtual network segment
**Result**: Isolated test network at height ~57-62

### Issue 3: Topic Name Consistency
**Server Alpha**: Uses `/qnk/testnet/blocks` and `/qnk/testnet/acks`
**Server Beta**: Unknown - may use `/qnk/mainnet/blocks`
**Impact**: If topics don't match, gossipsub messages won't propagate

### Fix 3: Add Bootstrap Retry Logic with Exponential Backoff

**Enhancement** (optional - for future robustness):
```rust
fn fetch_bootstrap_peers_with_retry(url: &str, max_retries: u8) -> Result<Vec<String>> {
    let mut retry_delay = Duration::from_secs(2);

    for attempt in 1..=max_retries {
        match Self::fetch_bootstrap_peers(url) {
            Ok(peers) if !peers.is_empty() => {
                info!("✅ Bootstrap discovery succeeded on attempt {}", attempt);
                return Ok(peers);
            }
            Ok(_) => {
                warn!("⚠️  Attempt {}/{}: No peers found", attempt, max_retries);
            }
            Err(e) => {
                warn!("⚠️  Attempt {}/{}: {}", attempt, max_retries, e);
            }
        }

        if attempt < max_retries {
            std::thread::sleep(retry_delay);
            retry_delay *= 2; // Exponential backoff
        }
    }

    Err(anyhow::anyhow!("Bootstrap discovery failed after {} attempts", max_retries))
}
```
