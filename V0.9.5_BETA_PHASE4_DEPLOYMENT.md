## 🚨 CRITICAL: Database Reset Required on Server Beta

### Why Reset is Needed:

Server Beta currently has 8000+ blocks on `testnet-phase2`:
- Cannot mix phase2 and phase4 blocks in same database
- Network ID mismatch will cause perpetual rejections
- Must start fresh genesis on phase4

### What Will Be Lost:

- **Blockchain**: All 8000+ blocks (testnet-phase2)
- **Balances**: All wallet balances
- **Transactions**: All transaction history

### What Will Be Preserved:

- **Software**: Latest v0.9.5-beta code
- **Configuration**: Node ID, ports, systemd service
- **Downloads**: User download binaries in nginx folder

## 📋 Server Beta Reset Procedure

### Step 1: Stop the Service
```bash
sudo systemctl stop q-api-server
```

### Step 2: Backup Current Database (Optional)
```bash
# Backup to safe location in case of rollback
sudo tar -czf /root/q-narwhalknight-phase2-backup-$(date +%Y%m%d).tar.gz \
  /opt/orobit/shared/q-narwhalknight/data-*
```

### Step 3: Delete Phase2 Database
```bash
# Remove all blockchain data (IRREVERSIBLE!)
sudo rm -rf /opt/orobit/shared/q-narwhalknight/data-*

# Verify deletion
ls -la /opt/orobit/shared/q-narwhalknight/ | grep data-
```

**Expected**: No `data-*` directories should exist

### Step 4: Deploy v0.9.5-beta Binary
```bash
# Copy new binary
sudo cp /opt/orobit/shared/q-narwhalknight/target/release/q-api-server \
  /opt/orobit/shared/q-narwhalknight/gui/quantum-wallet/dist-final/downloads/q-api-server-v0.9.5-beta

sudo cp /opt/orobit/shared/q-narwhalknight/target/release/q-api-server \
  /opt/orobit/shared/q-narwhalknight/gui/quantum-wallet/dist-final/downloads/q-api-server-linux-x86_64

# Make executable
sudo chmod +x /opt/orobit/shared/q-narwhalknight/gui/quantum-wallet/dist-final/downloads/q-api-server-v0.9.5-beta
sudo chmod +x /opt/orobit/shared/q-narwhalknight/gui/quantum-wallet/dist-final/downloads/q-api-server-linux-x86_64
```

### Step 5: Start Fresh on Phase4
```bash
sudo systemctl start q-api-server
sudo journalctl -u q-api-server -f
```

**Expected Logs**:
```

🌐 Network ID: testnet-phase4

```

## 📦 Server Alpha Deployment

### No Database Reset Needed

Server Alpha is already on phase4 (or has minimal phase2 blocks). Simply deploy new binary.

### Deployment Steps:

1. **SSH to Server Alpha**:
```bash
ssh root@161.35.219.10
```

2. **Download v0.9.5-beta**:
```bash
wget https://quillon.xyz/downloads/q-api-server-v0.9.5-beta
chmod +x q-api-server-v0.9.5-beta
```

3. **Stop Old Container**:
```bash
docker stop q-v0.8.10-beta
docker rm q-v0.8.10-beta
```

4. **Optional: Reset Database (if stuck)**:
```bash
# If Server Alpha has phase2 data causing issues
rm -rf /root/data-docker-alpha/*
```

5. **Start v0.9.5-beta**:
```bash
docker run -d --name q-v0.9.5-beta \
  -p 8080:8080 -p 9001:9001 \
  -v /root/data-docker-alpha:/data \
  -v /root/q-api-server-v0.9.5-beta:/usr/local/bin/q-api-server \
  -e Q_DB_PATH=/data \
  --restart unless-stopped \
  debian:bookworm-slim \
  /usr/local/bin/q-api-server --port 8080
```

6. **Monitor Logs**:
```bash
docker logs q-v0.9.5-beta -f
```
