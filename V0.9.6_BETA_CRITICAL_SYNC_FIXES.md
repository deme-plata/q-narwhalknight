### **Flaw #3: Gossipsub Topic Subscription Mismatch** ✅ FIXED

**Problem**: Hardcoded turbo sync topic names didn't include network prefix, causing publisher/subscriber topic mismatch.

**Impact**:
- Nodes subscribed to `/qnk/testnet-phase4/peer-heights` but publishers used `/qnk/testnet-phase2/peer-heights`
- Peer height announcements NEVER delivered - InsufficientPeers error
- TurboSync peer registry remained empty
- Sync failed: "No peers available with target height"

**Root Cause**:
```rust
// ❌ WRONG - Hardcoded topic in main.rs:918-920
let block_pack_requests_topic = format!("/qnk/{}/block-pack-requests", NETWORK_ID);
let peer_heights_topic = format!("/qnk/{}/peer-heights", NETWORK_ID);

// But network manager subscribed to:
// ✅ /qnk/testnet-phase4/peer-heights (using NetworkId enum)

// Result: Topic mismatch → messages never delivered!
```

**What Was Fixed**:

#### 1. **Added Helper Methods to NetworkId** (`q-types/src/lib.rs:723-742`)

**NEW**:
```rust
impl NetworkId {
    /// Get the peer-heights gossipsub topic for this network (Turbo Sync height announcements)
    /// ✅ v0.9.6-beta: Network-aware to prevent cross-network contamination
    pub fn peer_heights_topic(&self) -> String {
        format!("{}/peer-heights", self.gossipsub_topic_prefix())
    }

    /// Get the block-pack-requests gossipsub topic for this network (Turbo Sync requests)
    pub fn block_pack_requests_topic(&self) -> String {
        format!("{}/block-pack-requests", self.gossipsub_topic_prefix())
    }

    /// Get the block-pack-responses gossipsub topic for this network (Turbo Sync responses)
    pub fn block_pack_responses_topic(&self) -> String {
        format!("{}/block-pack-responses", self.gossipsub_topic_prefix())
    }
}
```

#### 2. **Updated Subscriptions** (`main.rs:916-938`)

**BEFORE**:
```rust
let block_pack_requests_topic = format!("/qnk/{}/block-pack-requests", NETWORK_ID); // ❌ Hardcoded!
let peer_heights_topic = format!("/qnk/{}/peer-heights", NETWORK_ID);               // ❌ Hardcoded!
```

**AFTER**:
```rust
// ✅ v0.9.6-beta: CRITICAL FIX - Network-aware topics prevent gossipsub subscription mismatch
let turbo_network_id = network_config.network_id.clone();
let block_pack_requests_topic = turbo_network_id.block_pack_requests_topic();
let peer_heights_topic = turbo_network_id.peer_heights_topic();
```

#### 3. **Updated Publishers** (`main.rs:3015-3023`)

**BEFORE**:
```rust
let _ = network_clone.send(q_network::NetworkCommand::PublishBlock {
    topic: format!("/qnk/{}/peer-heights", NETWORK_ID).to_string(), // ❌ Hardcoded!
    block_bytes: bytes,
    block_height: height,
});
```

**AFTER**:
```rust
// ✅ v0.9.6-beta: Network-aware peer-heights topic
let network_id = q_types::NetworkId::Testnet;

    topic: network_id.peer_heights_topic(),  // ✅ Matches subscription!
    block_bytes: bytes,
    block_height: height,
});
```

**Result**: Publisher and subscriber topics NOW MATCH → Messages delivered successfully!

### **Flaw #2: Network ID Validation Loop Bug** ✅ FIXED

**Problem**: `continue` statement in wrong scope rejected ENTIRE batch if ONE block had wrong network_id.

**Impact**:
- If batch had 1 invalid block + 999 valid blocks → ALL rejected
- Appeared as "no blocks received" instead of "partial batch processed"
- Valid sync progress lost

**What Was Fixed** (`main.rs:2245-2282`):

**BEFORE**:
```rust
for (idx, block) in batch_response.blocks.iter().enumerate() {
    if block.header.network_id != EXPECTED_NETWORK_ID {
        warn!("🚫 REJECTED block {}", idx);
        continue; // ← Skips to NEXT GOSSIPSUB MESSAGE, not next block!
    }
    // Process block...
}
```

**AFTER**:
```rust
// ✅ v0.9.6-beta: Filter blocks, process partial batches
let mut valid_blocks = Vec::new();
let mut rejected_count = 0;

for (idx, block) in batch_response.blocks.iter().enumerate() {
    if block.header.network_id != EXPECTED_NETWORK_ID {
        error!("🚫 REJECTED block {} - wrong network_id", idx);
        rejected_count += 1;
        continue; // ← NOW skips to next block, not next message!
    }
    valid_blocks.push(block.clone());
}

// Only skip message if ALL blocks invalid
if valid_blocks.is_empty() {
    error!("🚨 ALL BLOCKS REJECTED - NETWORK MISMATCH!");
    continue; // ← NOW skip message when appropriate
}

// Process valid_blocks (partial batch OK!)
```

**Result**: Partial batches now processed successfully!

**Evidence** (from logs):
```
Server Alpha requested blocks 1503-5838
Server Beta received: start_height=49, end_height=52  ← WRONG! Corruption!
```

**Root Cause**: `protocol_version` field added in v0.8.8, but old nodes don't have it. Binary deserialization misaligns struct fields.

**What Was Fixed** (`main.rs:2517-2538`):

**BEFORE**:
```rust
if let Err(e) = request.detect_corruption() {
```

```rust
if let Err(e) = request.detect_corruption() {
```

### **Flaw #2: Network ID Validation Loop Bug** ✅ FIXED

**Problem**: `continue` in network_id validation loop was in wrong scope - skipped entire gossipsub message instead of just invalid block.

**Location**: `main.rs:2245-2254`

**Bug**:
```rust
for (idx, block) in batch_response.blocks.iter().enumerate() {
    if block.header.network_id != EXPECTED_NETWORK_ID {
        warn!("REJECTED block {}", idx);
        continue; // ← BUG: Skips to NEXT GOSSIPSUB MESSAGE, not next block!
    }
}

// Process blocks...  ← NEVER REACHED if ANY block has wrong network_id!
```

**Result**:
- If peer sends 100 blocks, and 1 has wrong network_id → ALL 100 REJECTED
- Node appears to receive NO blocks even though 99 were valid
- Silent failure - user sees "no sync progress"

**What Was Fixed** (`main.rs:2245-2282`):

**AFTER** (v0.9.6-beta):
```rust
let mut valid_blocks = Vec::new();
let mut rejected_count = 0;

for (idx, block) in batch_response.blocks.iter().enumerate() {
    if block.header.network_id != EXPECTED_NETWORK_ID {
        error!("🚫 [BATCH SYNC] REJECTED block {} (height {}) - wrong network_id: '{}' (expected: '{}')",
              idx, block.header.height, block.header.network_id, EXPECTED_NETWORK_ID);
        error!("   This could be a testnet-phase1/mainnet block - REFUSING to process!");
        rejected_count += 1;
        continue; // ✅ NOW skips THIS block only!
    }
    valid_blocks.push(block.clone());
}

// If ALL blocks invalid, THEN skip message
if valid_blocks.is_empty() {
    error!("━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━");
    error!("🚨 CRITICAL: ALL BLOCKS IN BATCH REJECTED - NETWORK MISMATCH!");
    error!("━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━");
    error!("   Rejected {} blocks with wrong network_id", rejected_count);
    error!("   Expected: '{}'", EXPECTED_NETWORK_ID);
    error!("   Peer may be on different network (phase1/mainnet/etc)");
    error!("━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━");
    continue; // ✅ NOW skip to next gossipsub message
}

if rejected_count > 0 {
    warn!("⚠️  [BATCH SYNC] Partial batch: {} valid blocks, {} rejected",
          valid_blocks.len(), rejected_count);
}

let blocks = valid_blocks; // ✅ Only process valid blocks!
// Process blocks...  ← NOW REACHED with partial batch!
```

**Impact**:
- Partial batches now work - processes valid blocks even if some invalid
- LOUD error if ALL blocks rejected
- Clear visibility into what's happening
