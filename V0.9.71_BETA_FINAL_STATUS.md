## Summary

v0.9.71-beta removes legacy gossipsub block-pack infrastructure that was causing "Failed to decode BlockPackRequest" error messages. These errors were cosmetic (old gossipsub handler trying to process incompatible messages) but cluttering logs.

### What Changed

**Removed legacy gossipsub subscriptions**:
- Disabled `block-pack-requests` topic subscription
- Disabled `block-pack-responses` topic subscription
- Kept `peer-heights` topic (still needed for peer discovery)

**Disabled legacy gossipsub handler**:
- Wrapped old handler in `if false` block
- Added deprecation notices
- Prevents deserialization errors without removing code

## Technical Context

### Why These Errors Occurred

**v0.9.68-beta (original implementation)**:
- Implemented BlockPackCodec infrastructure
- BUT kept old gossipsub subscriptions active
- Old gossipsub handler still trying to process messages

**Network has mixed versions**:
- Some nodes send CBOR-encoded BlockPackCodec messages (v0.9.70+)
- Some nodes send old postcard-encoded messages (pre-v0.9.68)
- Old gossipsub handler can't decode CBOR → "Failed to decode" errors

**v0.9.70-beta solution**:
- Uses proper BlockPackCodec request-response protocol
- BUT old gossipsub subscriptions still active → errors continue

**v0.9.71-beta final fix**:
- Removes old gossipsub subscriptions
- Disables old gossipsub handler
- BlockPackCodec continues working (proper request-response)
- Errors gone, logs clean
