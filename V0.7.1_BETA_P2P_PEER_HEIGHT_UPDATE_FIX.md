## 🔍 Root Cause Analysis

### Issue 1: Peer Height Announcements Only Sent Every 30 Seconds

**File:** `crates/q-api-server/src/main.rs:2490`

```rust
tokio::spawn(async move {
    let mut interval = tokio::time::interval(std::time::Duration::from_secs(30));
    info!("🚀 [TURBO SYNC] Starting peer height announcement task (30s interval)");
```

**Problem:**
- Peer announces height 835 at 07:09:44
- Peer mines more blocks → reaches height 6,910
- Next announcement won't be sent until 07:10:14 (30 seconds later)
- Server Alpha receives stale height (835) and never gets updates

### Issue 2: No Re-Announcement When New Blocks Are Mined

**Current behavior:**
1. Peer mines blocks 1 → 835
2. Announces height 835 on 30-second timer
3. Server Alpha receives announcement and registers peer at height 835
4. Peer continues mining 836 → 6,910
5. **No announcement sent** until next 30-second interval
6. Server Alpha's peer registry remains at 835 (stale)

### Issue 3: Slow Height Updates Don't Match Mining Speed

**Timeline:**
- 07:09:44: Peer announces height 835
- 07:09:45: Server Alpha needs blocks up to 6,910
- Gap: 6,075 blocks mined since last announcement
- **Mining rate:** ~200 blocks/30sec = 6.7 blocks/sec
- **Announcement rate:** Once every 30 seconds = 0.033 announcements/sec

**Mismatch:** Mining is 200x faster than announcements!

## ✅ Solution: Increase Peer Height Announcement Frequency

### Fix 1: Reduce Announcement Interval from 30s → 5s

**File:** `crates/q-api-server/src/main.rs:2490`

**Change:**
```rust
// OLD (30-second interval - TOO SLOW)
let mut interval = tokio::time::interval(std::time::Duration::from_secs(30));
info!("🚀 [TURBO SYNC] Starting peer height announcement task (30s interval)");

// NEW (5-second interval - 6x faster updates)
let mut interval = tokio::time::interval(std::time::Duration::from_secs(5));
info!("🚀 [TURBO SYNC] Starting peer height announcement task (5s interval for fast discovery)");
```

**Benefits:**
- ✅ Peer heights update 6x faster
- ✅ Stale heights last maximum 5 seconds (vs 30 seconds)
- ✅ Turbo sync can find current peers quickly
- ✅ Minimal network overhead (40 bytes every 5 seconds per peer)

### Fix 2: Announce Immediately When New Blocks Are Mined

**File:** `crates/q-api-server/src/main.rs` (block production handler)

**Add to block broadcast logic (around line 2700):**
```rust
// After broadcasting block to P2P network
if let Some(network_tx) = &app_state.libp2p_command_tx {
    // Immediately announce our new height to help peers discover us
    let peer_id = {
        let info = app_state.libp2p_peer_info.read().await;
        info.0.clone()
    };

    #[derive(serde::Serialize, serde::Deserialize)]
    struct PeerHeightAnnouncement {
        peer_id: String,
        highest_block: u64,
    }

    let announcement = PeerHeightAnnouncement {
        peer_id,
        highest_block: verified_block.header.height,
    };

    if let Ok(announcement_bytes) = postcard::to_allocvec(&announcement) {
        let _ = network_tx.send(q_network::NetworkCommand::PublishBlock {
            topic: format!("/qnk/{}/peer-heights", NETWORK_ID),
            block_bytes: announcement_bytes,
            block_height: verified_block.header.height,
        });

        debug!("📡 [TURBO SYNC] Immediately announced new height {} after mining",
               verified_block.header.height);
    }
}
```

**Benefits:**
- ✅ Peers learn about new blocks instantly (not 30 seconds later)
- ✅ Real-time peer height tracking
- ✅ Turbo sync can activate as soon as peer gets ahead
- ✅ Decentralized sync without HTTP fallback

### Fix 3: Add Peer Height Expiration (Cleanup Stale Entries)

**File:** `crates/q-storage/src/turbo_sync.rs` (register_peer function)

**Add timestamp tracking:**
```rust
/// Peer registry with timestamps for expiration
peer_registry: Arc<RwLock<Vec<(PeerId, u64, std::time::Instant)>>>, // (peer_id, height, last_seen)
```

**Update register_peer:**
```rust
pub async fn register_peer(&self, peer_id: PeerId, highest_block: u64) {
    let mut registry = self.peer_registry.write().await;
    let now = std::time::Instant::now();

    // Update or insert with timestamp
    if let Some(entry) = registry.iter_mut().find(|(p, _, _)| p == &peer_id) {
        entry.1 = highest_block;
        entry.2 = now; // Update last_seen timestamp
    } else {
        registry.push((peer_id, highest_block, now));
    }

    // 🧹 Clean up stale entries (not seen in 60 seconds)
    registry.retain(|(_, _, last_seen)| last_seen.elapsed().as_secs() < 60);

    info!("📡 Registered peer {} with height {} (registry size: {})",
          peer_id, highest_block, registry.len());
}
```

**Benefits:**
- ✅ Removes peers that stopped announcing (disconnected/crashed)
- ✅ Prevents turbo sync from waiting for dead peers
- ✅ Keeps peer registry accurate and fresh
