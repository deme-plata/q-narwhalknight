## 🏗️ Banking System Architecture

### Existing Backend Infrastructure

#### QuillonBankSystem (/opt/orobit/shared/q-narwhalknight/crates/q-quillon-bank/)
- **CDP (Collateralized Debt Position)** minting for QUGUSD
- Already handles QUG as collateral (lines 304-318 in quillon_bank_api.rs)
- Collateral ratio: 150% minimum (lines 309-311)
- Base units: 1 QUGUSD = 100,000,000 frontend units = 1,000,000,000,000 backend units

#### API Endpoints (/opt/orobit/shared/q-narwhalknight/crates/q-api-server/src/quillon_bank_api.rs)

**Public Endpoints** (No Authentication):
- `GET /api/bank/stablecoin/status` - QUGUSD supply and collateral
- `GET /api/bank/metrics` - Banking metrics
- `GET /api/bank/risk/status` - Risk assessment
- `GET /api/bank/quantum/status` - Quantum features status
- `GET /api/bank/stablecoin/collateral` - Collateral composition
- `GET /api/bank/stablecoin/peg` - Peg status
- `GET /api/bank/lending/applications` - Loan applications (STUB)
- `GET /api/bank/lending/at-risk` - At-risk loans
- `GET /api/bank/treasury/reserves` - Reserve status
- `GET /api/bank/devfee/status` - Development fee transparency

**Protected Endpoints** (FOUNDER-ONLY via AEGIS-QL):
- `POST /api/bank/stablecoin/mint` - Mint QUGUSD (lines 246-418)
- `POST /api/bank/stablecoin/burn` - Burn QUGUSD
- `POST /api/bank/stablecoin/collateral/add` - Add collateral
- `POST /api/bank/lending/approve` - Approve loans (STUB)
- `POST /api/bank/lending/liquidate` - Liquidate loans (STUB)

#### Minting Process (Existing - Will Adapt for Loans)
1. User specifies QUGUSD amount and QUG collateral
2. Backend validates collateral ratio (150% minimum)
3. Backend locks QUG collateral (deducts from wallet balance)
4. Backend mints QUGUSD tokens
5. Backend updates balances in token_balances map
6. Backend persists to storage
7. Backend broadcasts SSE `balance-updated` event

## 🎯 Loan Application Flow

### User Journey:
1. User navigates to Dashboard
2. User sees "My Wallets" section showing QUG and QUGUSD balances
3. User clicks "Apply for Loan" button
4. Modal opens with loan application form
5. User enters desired QUGUSD loan amount
6. System calculates required QUG collateral (150% ratio)
7. System displays:
   - Collateral required
   - Interest rate (based on credit score, ratio, term)
   - Monthly payment amount
   - Loan term options
8. User reviews and submits application
9. Backend processes application:
   - Validates wallet has sufficient QUG
   - Locks QUG collateral
   - Mints QUGUSD to borrower
   - Creates loan record
   - Emits SSE balance-updated event
10. Frontend shows success message
11. User's QUGUSD balance updates in real-time via SSE

### Loan Repayment (Future Enhancement):
- Monthly payment deducted from QUGUSD balance
- Interest calculated on remaining principal
- Collateral released after full repayment
- Auto-liquidation if collateral ratio drops below 120%

## 🔧 Technical Details

### Balance Update Events (SSE)
**Event Type**: `balance-updated`
**Data Structure**:
```json
{
  "wallet_address": "qnk<hex>",
  "new_balance": 123456789,
  "change_reason": "CDP_MINT"
}
```

### Collateral Ratio Calculation
```
Collateral Ratio = (Collateral Value USD / Loan Amount USD) * 100
Minimum Ratio: 150%
Liquidation Threshold: 120%
```

### Interest Rate Calculation (Proposed)
```
Base Rate: 5% APR
+ Credit Score Adjustment: -2% to +5%
+ Collateral Ratio Bonus: -1% per 10% above 150%
+ Term Premium: +0.5% per 6 months

Example:
- 12-month loan, 200% collateral, good credit score
- Rate: 5% (base) - 1% (credit) - 1% (high collateral) + 1% (term) = 4% APR
```
