**Date**: 2025-11-09

## Problem

**Turbo sync was completely broken** - peers never responded to block pack requests because we were using the wrong protocol.

### Root Cause
- Using **gossipsub** (pub/sub broadcast) for request/response pattern
- NO HANDLER existed to receive requests and send responses
- 100% timeout rate → HTTP fallback only → **7+ days to sync 5000 blocks**

### Symptoms
- Sync rate: 0.5 blocks/minute via HTTP fallback
- All block pack requests timeout after 90 seconds
- Node stuck at height 316, network at 5281
- Estimated 7+ days to catch up

---

## Solution

Replaced gossipsub turbo sync with **proper libp2p request-response protocol**.

### Architecture Change

**Before (Broken)**:
```
Node A → Gossipsub broadcast → ??? (nobody listening)
       ↓
   90s timeout
       ↓
  HTTP fallback (0.5 blocks/min)
```

**After (Proper)**:
```
Node A → Request-Response → Node B receives request
                                ↓
                          Loads blocks from DB
                                ↓
                          Sends response
                                ↓
Node A ← 1000 blocks in 1-5 seconds
```

pub fn request_blocks_from_peer(&mut self, peer_id: PeerId, start_height: u64, limit: usize) {
    let end_height = start_height + limit as u64 - 1;
    let request = BlockPackRequest::new(start_height, end_height);

### 3. Request Handler (q-network/src/unified_network_manager.rs)

**Incoming Request Handler**:
```rust
Message::Request { request, channel, .. } => {
    // Validate request
    request.validate()?;

    // Fetch blocks from storage
    let blocks = storage.get_qblocks_range(
        request.start_height,
        request.max_blocks
    ).await?;

    // Send response
    let response = BlockPackResponse::from_blocks(blocks, request.end_height);
    swarm.behaviour_mut().block_sync.send_response(channel, response)?;
}
```

**Response Handler**:
```rust
Message::Response { response, .. } => {
    // Forward blocks to consensus for validation
    block_sync_tx.send(response.blocks)?;
}
```

## Technical Details

### libp2p Request-Response Protocol

**What is it?**
- Built-in libp2p protocol for 1:1 request/response communication
- Proper request/response correlation via request IDs
- Automatic timeout handling
- Peer routing built-in

**Why not gossipsub?**
- Gossipsub = **pub/sub** (broadcast to all subscribers)
- Request-Response = **RPC** (direct 1:1 communication)
- Using gossipsub for RPC is architecturally wrong (like using a megaphone when you need a phone)

### CBOR Serialization

**Why CBOR?**
- Binary format (30-50% smaller than JSON)
- Fast parsing (no text conversion)
- Perfect for large payloads (1000 blocks = 1-5 MB)

**Example**:
```
JSON:  {"start_height": 1000, "end_height": 2000}  // 50 bytes
CBOR:  0xa2 0x6c 0x73...                          // 30 bytes (40% smaller)
```
