**Impact**: Fresh nodes fall back to slow HTTP sync, cannot keep up with live block production.

**Status**: v0.9.55-beta deployed with genesis fix working, but NEW deserialization corruption issue blocking turbo sync.

## Root Cause Analysis

### The Corrupted Value: 1762590545

```
Hex representation: 0x690eff51

As little-endian bytes: 51 ff 0e 69 00 00 00 00
As big-endian bytes: 00 00 00 00 69 0e ff 51

As varint (postcard encoding): d1 fe bb c8 06 (5 bytes)
```

**Analysis**:
- NOT a simple byte-swap issue (byte-swapped would be 1375669865, not 1762590545)
- NOT a simple misinterpretation of protocol_version=1 as start_height
- Appears to be memory corruption or encoding mismatch

### Hypothesis 1: Protocol Version Mismatch

The code has v0.9.53-beta backward compatibility logic:

**File**: `crates/q-storage/src/turbo_sync.rs:157-212`

```rust
pub fn from_bytes(data: &[u8]) -> Result<Self> {
    // Version detection by inspecting first byte
    let is_new_format = data[0] == 0x01;

    if is_new_format {
        // Try NEW format (with protocol_version field)
        match postcard::from_bytes::<Self>(data) {
            Ok(req) => { /* validate and return */ }
            Err(e) => {
                // NEW format failed, try OLD format
                Self::decode_old_format(data)
            }
        }
    } else {
        // First byte is NOT 0x01, definitely OLD format
        Self::decode_old_format(data)
    }
}
```

**Possible Issue**:
- Server Beta (v0.9.55) sends NEW format: `[protocol_version=1, start_height, end_height, request_id]`
- Server Alpha (v0.9.55) receives and tries to decode
- First byte is `0x01` → tries NEW format
- NEW format deserialization SUCCEEDS (postcard doesn't error)
- BUT height validation FAILS with corrupted value 1762590545

**Why This Might Happen**:

When v0.9.53-beta comment says "REMOVED #[serde(default)] from protocol_version", it suggests that OLDER binaries might still have `#[serde(default)]` which causes postcard to SKIP the field during deserialization.

**Scenario**:
1. Server Beta (v0.9.55-beta) sends: `[0x01, 0x9a 0x75, 0x9d 0x81 0x01, ...]`
   - protocol_version = 1 (varint: `0x01`)
   - start_height = 15002 (varint: `0x9a 0x75`)
   - end_height = 16541 (varint: `0x9d 0x81 0x01`)

2. Server Alpha (v0.9.55-beta) receives and decodes:
   - If BOTH are on v0.9.55-beta, should work fine
   - If Server Alpha is ACTUALLY running an OLDER version (v0.9.52-beta or earlier), it might have `#[serde(default)]` still

3. With `#[serde(default)]`, postcard SKIPS protocol_version during deserialization:
   - Reads `0x01` as start of start_height varint
   - Continues reading subsequent bytes as part of start_height
   - Creates corrupted value

## Deserialization Corruption Mechanism

### When OLD binary (v0.9.52 or earlier) tries to decode NEW format from v0.9.55:

**NEW format bytes** (from v0.9.55 Server Beta):
```
Bytes: 01 9a75 9d8101 [request_id bytes...]
       │  │    │
       │  │    └─ end_height = 16541
       │  └───── start_height = 15002
       └─────── protocol_version = 1
```

**OLD binary decoding** (with `#[serde(default)]`):
```rust
// postcard sees data[0] = 0x01
// Because of #[serde(default)], postcard SKIPS protocol_version field
// Treats 0x01 as first byte of start_height!

// Reads start_height varint:
// 0x01 → (byte & 0x80) == 0, so this is the LAST byte
// start_height = 1

// Reads end_height varint:
// 0x9a 0x75 → end_height = 15002

// But wait... the OLD binary expects request_id next!
// It starts reading request_id from the bytes that are actually end_height!
// This causes COMPLETE CORRUPTION of all subsequent fields
```

**Result**: Corrupted height values like 1762590545 appear!

### Option 2: Add Stricter Protocol Version Validation

**File**: `crates/q-storage/src/turbo_sync.rs:160-198`

Add logging to CONFIRM which format is being decoded:

```rust
pub fn from_bytes(data: &[u8]) -> Result<Self> {
    if data.is_empty() {
        anyhow::bail!("Empty BlockPackRequest data");
    }

    // ✅ v0.9.56-beta: Log received bytes for debugging
    tracing::info!("🔍 [TURBO SYNC DEBUG] Received BlockPackRequest bytes (len={}): {:02x?}",
                   data.len(), &data[..data.len().min(64)]);

    let is_new_format = data[0] == 0x01;

    tracing::info!("🔍 [TURBO SYNC DEBUG] Format detection: first_byte=0x{:02x}, is_new_format={}",
                   data[0], is_new_format);

    if is_new_format {
        // Try NEW format
        match postcard::from_bytes::<Self>(data) {
            Ok(req) => {
                tracing::info!("✅ [TURBO SYNC DEBUG] NEW format decoded: protocol_version={}, start={}, end={}, id={}",
                               req.protocol_version, req.start_height, req.end_height, req.request_id);

                // ✅ v0.9.56-beta: Validate heights BEFORE validation function
                if req.start_height > 100_000_000 {
                    tracing::error!("❌ [TURBO SYNC DEBUG] CORRUPTED start_height={} detected AFTER postcard decode!",
                                    req.start_height);
                    tracing::error!("❌ [TURBO SYNC DEBUG] This suggests the sender is using OLD format with #[serde(default)]!");
                    tracing::error!("❌ [TURBO SYNC DEBUG] Raw bytes: {:02x?}", data);

                    // Try OLD format as fallback
                    tracing::warn!("⚠️  [TURBO SYNC DEBUG] Attempting OLD format decode as fallback...");
                    return Self::decode_old_format(data);
                }

                req.validate_heights()?;
                Ok(req)
            }
            Err(e) => {
                tracing::warn!("⚠️  NEW format decode failed: {}, trying OLD format", e);
                Self::decode_old_format(data)
            }
        }
    } else {
        tracing::info!("🔍 [TURBO SYNC DEBUG] Using OLD format decode (first byte != 0x01)");
        Self::decode_old_format(data)
    }
}
```

### Option 3: Remove Backward Compatibility Entirely

If BOTH nodes are guaranteed to be v0.9.53-beta or later, remove the OLD format support entirely:

