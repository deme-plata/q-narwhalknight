## 🔍 Root Cause Analysis

### The Problem

The error occurred at **line 699** of `AIChatScreen.tsx`:

```typescript
{messages.map((message) => (
  // ... render message
```

The `messages` state variable was being set to a non-array value, causing `.map()` to fail.

### Why It Happened

**Two bugs existed:**

1. **Bug in initial mount polling** (lines 159-186):
   - When component mounted and detected ongoing generation, it called `setMessages(backendMessages)` 
   - **Problem**: Didn't check if `backendMessages` was the API response wrapper `{success: true, data: [...]}` or just the array
   - Set `messages` state to the entire response object instead of the `data` array

2. **No defensive rendering** (line 699):
   - The render code assumed `messages` was always an array
   - **Problem**: No `Array.isArray()` check before calling `.map()`
   - When state became non-array, crash was inevitable

---

## ✅ Fix Applied

### Fix 1: Safe Polling on Mount (lines 159-186)

**Before**:
```typescript
const backendMessages = await response.json();
setMessages(backendMessages); // ❌ WRONG - sets entire response object

const lastMsg = backendMessages[backendMessages.length - 1]; // ❌ Tries to index an object
```

**After**:
```typescript
const backendMessages = await response.json();

// ✅ Check response structure
if (backendMessages.success && Array.isArray(backendMessages.data)) {
  setMessages(backendMessages.data); // ✅ CORRECT - sets only the array
  
  // ✅ Access array correctly
  const lastMsg = backendMessages.data[backendMessages.data.length - 1];
}
```

### Fix 2: Defensive Rendering (line 699)

**Before**:
```typescript
{messages.map((message) => ( // ❌ Crashes if messages is not an array
```

**After**:
```typescript
{Array.isArray(messages) && messages.map((message) => ( // ✅ Safe - checks before mapping
```

## 📝 Why This Fix Works

### Defense in Depth:

1. **Prevent the problem** (lines 168-180):
   - Validate API response structure before setting state
   - Only extract the `data` array from response
   - Add try/catch for network errors

2. **Recover gracefully** (line 707):
   - Even if state becomes invalid somehow, don't crash
   - `Array.isArray()` check returns `false` for non-arrays
   - Short-circuit prevents `.map()` from being called
   - UI shows empty messages instead of crashing
