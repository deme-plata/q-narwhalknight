## 🔐 WHAT'S NEW IN v0.9.15-beta

### AEGIS-QL Post-Quantum P2P Sync

#### 1. Signed Block Packs
Every block pack transmitted over P2P is now signed with AEGIS-QL post-quantum cryptography:
- **Merkle root**: O(1) integrity verification
- **AEGIS-QL signature**: Post-quantum authenticity
- **Timestamp**: Replay attack prevention (5-minute window)
- **Peer ID**: Track which peer sent blocks

#### 2. Sync Affirmation Certificates
Cryptographic proof that sync completed successfully:
- **Prevents restart loops**: Node knows it already synced
- **Merkle root of all blocks**: Cryptographic proof of completeness
- **AEGIS-QL signed**: Tamper-proof certificate
- **Stored in database**: Persists across restarts

#### 3. Peer Trust Registry
Automatic reputation tracking for all peers:
- **Trust score**: 0.0 - 1.0 (exponential moving average)
- **Valid signatures**: Increase trust
- **Invalid signatures**: Decrease trust significantly
- **Automatic banning**: Trust < 20% → peer banned
- **Trusted peers**: Trust >= 80% → prioritized for sync

#### 4. Dynamic Progress Logging
Real-time visibility into AEGIS-QL verification:

## 🔧 TROUBLESHOOTING

### Issue: "Failed to generate AEGIS-QL keypair"
**Cause**: q-aegis-ql dependency missing
**Fix**: Rebuild with `cargo build --release --package q-api-server`

### Issue: Peer trust scores all 0%
**Cause**: Peers not sending signed blocks (older version)
**Fix**: Upgrade all nodes to v0.9.15-beta

### Issue: Certificate not created after sync
**Cause**: Sync failed or blocks not persisted
**Fix**: Check logs for "SYNC AFFIRMED" message - if missing, check storage errors

### Issue: Still syncing after restart
**Cause**: Certificate not loaded or corrupted
**Fix**: Check for "Loaded sync certificate" log - if missing, certificate may be corrupted
