## ⚠️ REMAINING ISSUES (For v0.9.3-beta)

### Issue #1: `/api/v1/status` Endpoint Not Functional

**Problem**: Endpoint exists in code (registered at `main.rs:4828`) but hangs on requests

**Evidence**:
```bash
curl http://localhost:8080/api/v1/status
# Returns: Timeout (no response after 60+ seconds)
```

**Root Cause**: Lock contention in libp2p peer info cache due to network degradation

**Impact**: **Bootstrap peer discovery broken** - all nodes fail to fetch peer list

### Issue #2: Localhost-Only Peer Connections

**Problem**: Bootstrap node only connecting to `127.0.0.1` peers, zero external peers

**Evidence from logs**:
```
✅ [CONNECTION] Successfully connected to peer: 12D3KooWM5Z6jcZDQFsJeCxwZPXtUuJCJfvRGYNAAg93Xkg6x51M
📍 [CONNECTION] Endpoint: Listener { local_addr: /ip4/127.0.0.1/tcp/9001, send_back_addr: /ip4/127.0.0.1/tcp/9092 }
👋 [DISCONNECTION] Connection closed with peer (remaining peers: 0)
```

**Analysis**:
- All connections are to `127.0.0.1` (localhost)
- Connections immediately disconnect
- **ZERO external internet peers** connected

**Impact**: **Network isolation** - nodes cannot discover external peers

### Issue #3: mDNS-Only Peer Discovery

**Problem**: When bootstrap endpoint fails, nodes fall back to mDNS discovery only

**Evidence from client logs**:
```
WARN  ⚠️  Failed to fetch bootstrap peers from http://185.182.185.227:8080
INFO  ℹ️  No automatically discovered bootstrap peers - using static network config
INFO  ℹ️ No bootstrap peers configured - DHT will populate via mDNS discoveries
```

**Why This Breaks**:
- **mDNS scope**: Local subnet only (LAN/WiFi)
- **Cannot cross routers**: Internet discovery impossible
- **Result**: Nodes can only discover peers on their local network

**Impact**: **Zero internet-wide peer discovery**

### Issue #4: No Hardcoded Bootstrap Peers

**Problem**: No fallback bootstrap peer list in code

**Current Behavior**:
1. Node tries to fetch from `/api/v1/status` (fails/hangs)
2. Falls back to "No bootstrap peers" mode
3. Only mDNS active (local network only)
4. Network fragmentation results

**Expected Behavior**:
```rust
const BOOTSTRAP_PEERS: &[&str] = &[
    "/ip4/185.182.185.227/tcp/9001/p2p/12D3KooWRX3GGK9Fs3iM3BfqYNNJiHBDujac7EHwqWjaK1n1kzPN"
];
```

**Impact**: **No fallback for bootstrap discovery failures**

## 🚀 NEXT STEPS (v0.9.3-beta)

### Priority 1: Fix `/api/v1/status` Endpoint Lock Contention

**Analysis**: Endpoint hangs due to `libp2p_peer_info.read().await` timeout

**Possible Solutions**:
1. Use try_read with timeout instead of await
2. Cache peer info with stale-if-unavailable policy
3. Return bootstrap peer list without waiting for libp2p lock
4. Add dedicated bootstrap endpoint that doesn't depend on libp2p state

**Recommended Approach**: Create a simple `/api/v1/bootstrap` endpoint that returns hardcoded peer list immediately (no locks)

### Priority 2: Add Hardcoded Bootstrap Peer List

**Location**: `crates/q-network/src/unified_network_manager.rs`

**Implementation**:
```rust
const BOOTSTRAP_PEERS: &[&str] = &[
    "/ip4/185.182.185.227/tcp/9001/p2p/12D3KooWRX3GGK9Fs3iM3BfqYNNJiHBDujac7EHwqWjaK1n1kzPN"
];

// Use these as fallback when HTTP discovery fails
if discovered_peers.is_empty() {
    for addr in BOOTSTRAP_PEERS {
        swarm.dial(addr.parse()?)?;
    }
}
```

**Current State**: Kademlia DHT is enabled but not bootstrapping properly

**Required**: Ensure Kademlia bootstraps from hardcoded peers, not just mDNS
