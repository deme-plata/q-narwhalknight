### Continuous Height Monitor
```bash
#!/bin/bash
# save as /tmp/height-monitor.sh

LOGFILE="/tmp/height-progression-$(date +%Y%m%d).log"
echo "Starting height monitor at $(date)" | tee -a $LOGFILE
echo "Logging to: $LOGFILE"
echo ""

LAST_HEIGHT=0
STALL_COUNT=0

while true; do
    CURRENT_HEIGHT=$(curl -s localhost:8080/metrics 2>/dev/null | grep qnk_node_height | awk '{print $2}')
    TIMESTAMP=$(date +"%Y-%m-%d %H:%M:%S")

    if [ -z "$CURRENT_HEIGHT" ]; then
        echo "$TIMESTAMP ERROR: Could not fetch height (API down?)" | tee -a $LOGFILE
        sleep 10
        continue
    fi

    # Check for height advancement
    if [ "$CURRENT_HEIGHT" -eq "$LAST_HEIGHT" ]; then
        STALL_COUNT=$((STALL_COUNT + 1))
        if [ "$STALL_COUNT" -ge 6 ]; then  # 60 seconds stalled
            echo "$TIMESTAMP ⚠️  WARNING: Height stalled at $CURRENT_HEIGHT for $((STALL_COUNT * 10)) seconds" | tee -a $LOGFILE
        fi
    else
        if [ "$STALL_COUNT" -gt 0 ]; then
            echo "$TIMESTAMP ✅ Height advancing again: $LAST_HEIGHT → $CURRENT_HEIGHT (was stalled for $((STALL_COUNT * 10))s)" | tee -a $LOGFILE
        fi
        STALL_COUNT=0
    fi

    # Log height every minute
    if [ $(($(date +%s) % 60)) -lt 10 ]; then
        DELTA=$((CURRENT_HEIGHT - LAST_HEIGHT))
        echo "$TIMESTAMP Height: $CURRENT_HEIGHT (Δ$DELTA in 60s)" | tee -a $LOGFILE
    fi

    LAST_HEIGHT=$CURRENT_HEIGHT
    sleep 10
done
```

**Usage**:
```bash
chmod +x /tmp/height-monitor.sh
nohup /tmp/height-monitor.sh &
```

### If AsyncStorageEngine Queue Grows Unbounded

**Warning Threshold**: Queue depth >500 blocks
**Critical Threshold**: Queue depth >2000 blocks

**Immediate Actions**:
1. Check disk I/O:
   ```bash
   iostat -x 1 5
   ```

2. Check RocksDB write speed:
   ```bash
   journalctl -u q-api-server --since "30 seconds ago" | grep "AsyncStorageEngine: Block" | grep -oP 'queued in \K[0-9.]+ms'
   ```

**If Disk I/O is Saturated**: Storage bottleneck (hardware issue, not software bug)

**If Write Speed >100ms per block**: RocksDB may be compacting. Wait for completion.

**If Write Speed Normal but Queue Growing**: Possible async worker thread deadlock. Restart required.

## 🎓 LESSONS LEARNED & FUTURE IMPROVEMENTS

### Root Cause Analysis Insights

**What Went Right**:
1. ✅ AI consensus (3 independent AIs) correctly identified the bug with 85-95% confidence
2. ✅ Empirical evidence (AsyncStorageEngine queue empty during stall) ruled out storage I/O bottleneck
3. ✅ Code inspection confirmed the exact issue: missing `save_succeeded = true;`
4. ✅ Fix was surgical (3 lines of code) with minimal risk

**What Could Be Improved**:
1. ⚠️ Hybrid storage paths create multiple failure modes (both paths should update shared state)
2. ⚠️ Silent failures (height not advancing) are hard to detect without metrics
3. ⚠️ Timeout warnings (RwLock path) masked the real issue (async path not setting flag)

### Recommended Code Improvements (Future Work)

#### 1. **Unified Storage Success Tracking**
```rust
// Instead of a single boolean flag, use an enum:
enum StorageResult {
    AsyncSuccess,
    RwLockSuccess,
    NotYetSaved,
}

let mut storage_result = StorageResult::NotYetSaved;

// AsyncStorageEngine path
if async_storage.save_block(...).await.is_ok() {
    storage_result = StorageResult::AsyncSuccess;
}

// RwLock path (only if needed)
if matches!(storage_result, StorageResult::NotYetSaved) {
    if save_qblock(...).await.is_ok() {
        storage_result = StorageResult::RwLockSuccess;
    }
}

// Height advancement
match storage_result {
    StorageResult::AsyncSuccess | StorageResult::RwLockSuccess => {
        advance_height(...);
    }
    StorageResult::NotYetSaved => {
        error!("CRITICAL: Neither storage path succeeded!");
    }
}
```
