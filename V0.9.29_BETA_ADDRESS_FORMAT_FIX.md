## 🐛 **THE BUG**

**Symptom**: All wallet balance queries return 0 QUG despite balances being updated correctly in the background

**Root Cause**: Address format mismatch between balance storage and balance queries

### How It Worked (Incorrectly):

**Balance Storage** (`balance_consensus.rs`):
- Stores addresses as **16-character hex** (first 8 bytes)
- Example: `efca1e8c1f46e910`, `65085b6858d870be`

**Balance Query** (`handlers.rs:2688` in v0.9.28-beta):
```rust
let address_hex = hex::encode(&address_bytes);  // ❌ Uses full 64-char address
state.storage_engine.get_consensus_balance(&address_hex)
```

**Result**: Query looks for key `efca1e8c1f46e91013b4073898c771bb3d566453537ccf87e834505925e50723` but storage only has `efca1e8c1f46e910` → **MISMATCH** → Returns 0

---

## ✅ **THE FIX**

### File: `crates/q-api-server/src/handlers.rs:2689`

**Before** (v0.9.28-beta):
```rust
let address_hex = hex::encode(&address_bytes);  // Full 64 chars
```

**After** (v0.9.29-beta):
```rust
let address_hex = hex::encode(&address_bytes[..8]);  // First 8 bytes = 16 hex chars
```

This matches how balance consensus stores addresses!

## 🔍 **WHY THIS WASN'T CAUGHT EARLIER**

1. **Logs were misleading**: The log message at line 2697 used `hex::encode(&address_bytes[..8])` (correct), but the actual query at line 2688 used `hex::encode(&address_bytes)` (wrong)

2. **Balance updates appeared to work**: SSE broadcasts showed balances updating, but those were from in-memory cache, not database queries

3. **TIME-BASED transactions used short addresses**: The Phase 2 TIME-BASED coinbase transactions already used 16-char addresses, masking the issue

## 🛠️ **CARGO.TOML BUILD ISSUES ENCOUNTERED**

During v0.9.29-beta compilation, encountered Cargo dependency conflicts:

### Issue 1: Duplicate hf-hub Key Error (FALSE ERROR)
```
error: duplicate key
   --> Cargo.toml:364:1
    |
364 | hf-hub = { version = "0.4.2", default-features = false, features = ["ureq", "tokio", "rustls-tls"] }
    | ^^^^^^
```

**Root Cause**: This error message was **misleading**. Line 364 contained `mistralrs-paged-attn`, not `hf-hub`. The error was caused by **BOTH** `Cargo.toml` and `mistral.rs/Cargo.toml` defining `hf-hub` in their workspace dependencies.

### Issue 2: Workspace Inheritance vs Duplicate Definitions
- `mistralrs-core/Cargo.toml` uses `hf-hub.workspace = true` (expects parent workspace to define it)
- Both root `Cargo.toml` (line 131) and `mistral.rs/Cargo.toml` (line 90) defined `hf-hub`
- Cargo apparently allows this in some contexts but reports cryptic errors

### Resolution:
Keep BOTH `hf-hub` definitions (root Cargo.toml line 131 AND mistral.rs/Cargo.toml line 90). The "duplicate key" error was transient or related to cargo cache state.

**Lesson**: Don't trust Cargo error line numbers when dealing with workspace dependencies! The error location may not match the actual problem location.
