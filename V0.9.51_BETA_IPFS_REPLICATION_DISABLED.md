# v0.9.51-beta - IPFS Replication Disabled (Architecture Incompatibility)

**Date**: 2025-11-08 05:30 CET

**Type**: Critical production fix - Disable incompatible IPFS replication
**Status**: 🔧 **BUILDING**

## 📋 Executive Summary

v0.9.51-beta **DISABLES** IPFS database replication because it is fundamentally incompatible with our hot/cold RocksDB architecture. This feature has been causing recurring block production stalls every 5 minutes since it was introduced.

**Root Cause**: IPFS backup expects a single RocksDB database, but we have TWO separate instances (hot and cold).

**Impact**: Eliminates recurring block production stalls that occurred at heights 15511 and 15642.

## 🔍 Root Cause Analysis

### The Fundamental Architecture Mismatch

**IPFS Backup Expects** (`crates/q-ipfs-storage/src/snapshot.rs:74-78`):
```rust
// Open the database (read-only to avoid lock issues)
let db = DB::open_for_read_only(
    &rocksdb::Options::default(),
    db_path,  // ← Expects SINGLE RocksDB at this path
    false,
);
```

**Our Actual Database Structure**:
```
./data-mine5/                    ← NOT a RocksDB database
├── hot/                         ← SEPARATE RocksDB instance #1
│   ├── CURRENT                  ← RocksDB metadata
│   ├── MANIFEST-*
│   ├── *.sst
│   └── ...
├── cold/                        ← SEPARATE RocksDB instance #2
│   ├── CURRENT                  ← RocksDB metadata
│   ├── MANIFEST-*
│   ├── *.sst
│   └── ...
└── snapshots/
```

**The Conflict**:
1. IPFS tries to open `./data-mine5` as a RocksDB database
2. RocksDB expects `./data-mine5/CURRENT` file (database metadata)
3. File doesn't exist - CURRENT files are in `hot/` and `cold/` subdirectories
4. **Error**: "No such file or directory: ./data-mine5/CURRENT"
5. IPFS backup fails, blocks the database
6. Block producer can't save new blocks
7. **Height freezes**

### Why v0.9.50-beta Failed

v0.9.50-beta correctly configured the path to `./data-mine5`, but this revealed the DEEPER architectural incompatibility:

- ✅ Path configuration was correct
- ❌ **Architecture mismatch was the real problem**

IPFS replication was designed for single-instance RocksDB databases, not hot/cold split architecture.

---

## ✅ Solution: Disable IPFS Replication

### Changes Made

**File**: `crates/q-api-server/src/main.rs`
**Lines**: 4890-4902

```rust
// Create replication configuration
// v0.9.51-beta: DISABLE IPFS replication - incompatible with hot/cold database architecture
// IPFS backup tries to open ./data-mine5 as single RocksDB, but we have:
//   - ./data-mine5/hot/ (separate RocksDB instance)
//   - ./data-mine5/cold/ (separate RocksDB instance)
// This causes "No such file: ./data-mine5/CURRENT" errors every 5 minutes
// which block the database and stall block production
let replication_config = ReplicationConfig {
    enabled: false,  // v0.9.51-beta: DISABLED - incompatible with hot/cold DB
    snapshot_interval: 300,  // 5 minutes
    max_incremental_updates: 100,
    verify_updates: true,
    parallel_downloads: 10,
};
```

### Why This is the Correct Fix

1. **Eliminates the Error Source**: No more IPFS backup attempts
2. **Prevents Database Blocking**: No RocksDB read locks from failed backups
3. **Simple and Safe**: Single-line change with comprehensive documentation
4. **Backward Compatible**: IPFS replication was experimental, not production-critical
5. **Long-term Stability**: Removes recurring source of outages

## 🔍 Why IPFS Replication Was Attempted

### Original Goal (Well-Intentioned but Flawed)

IPFS replication was designed to provide:
- Distributed database backups across network nodes
- IPFS content-addressed snapshots
- Peer-to-peer database restoration

### Why It Failed

1. **Wrong Assumptions**: Assumed single RocksDB instance
2. **Hot/Cold Split**: Our architecture has TWO separate databases
3. **No Validation**: IPFS backup never tested with production DB structure
4. **Silent Failures**: Errors logged as WARN not ERROR
5. **Database Locking**: Failed read attempts blocked database writes

---

## 📝 Future IPFS Replication (If Needed)

If IPFS replication is needed in the future, it would require:

1. **Hot/Cold Aware Backup**:
   - Backup `./data-mine5/hot/` separately
   - Backup `./data-mine5/cold/` separately
   - Combine manifests for restoration

2. **Non-Blocking Design**:
   - Use database checkpoints instead of direct access
   - Async backup without holding locks
   - Graceful error handling

3. **Testing**:
   - Test with actual production database structure
   - Verify compatibility with hot/cold architecture
   - Integration tests before production

**For Now**: IPFS replication is DISABLED until proper implementation exists.
