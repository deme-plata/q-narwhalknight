Added loud, detailed logging to catch WHY the blockchain height recovery is failing. The new logging will tell us exactly what happens during startup.

### Code Changes

**What the new logging will show:**

1. **Before height recovery attempt:**
   ```
   🔍 [v0.6.6] Attempting to load blockchain height from database...
   🔍 [v0.6.6] Database path: "./data-mine1"
   ```

2. **On SUCCESS (height > 0):**
   ```

   ```

   ```
   ⚠️  [v0.6.6] Starting fresh blockchain at height 0
   ⚠️  [v0.6.6] If you expected blocks to be present, CHECK DATABASE INTEGRITY!
   ```

4. **On ERROR (database query failed):**
   ```
   🚨 [v0.6.6] CRITICAL ERROR: Failed to load blockchain height from database!
   🚨 [v0.6.6] Error: <actual error message>

   🚨 [v0.6.6] This will cause blockchain reset! Starting at height 0
   🚨 [v0.6.6] Node will re-sync from peers (slow but safe)
   ```

## 🔍 What This Will Diagnose

The new logging will definitively answer:

1. **Is the database path correct?**
   - We'll see the exact path being used
   - Can verify it matches where blocks are actually stored

2. **Does get_highest_contiguous_block() succeed or fail?**
   - Success path: Returns height > 0
   - Zero path: Returns 0 (no blocks found in database)
   - Error path: Returns an error (database corruption or access issue)

3. **What is the actual error if it fails?**
   - Previously: Silent failure with generic message
   - Now: Loud error with exact error message

4. **Was the height actually loaded correctly?**
   - Verification step shows final height before node starts
   - Can confirm height matches what we expect
