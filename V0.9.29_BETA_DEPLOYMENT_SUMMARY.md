## 🎯 FIXES INCLUDED IN v0.9.29-beta

### **FIX #1: Balance Query Bug (Zero Balance Display)**
**Severity**: HIGH - User-facing issue
**File**: `crates/q-api-server/src/handlers.rs:2689`

**Problem**:
- All wallet balances showing 0 QUG in frontend
- Balance consensus working correctly in background
- Address format mismatch: Storage uses 16-char hex (first 8 bytes), queries used full 64-char hex

**Root Cause**:
```rust
// ❌ BEFORE (v0.9.28-beta - BROKEN)
let address_hex = hex::encode(&address_bytes);  // Full 64-char address
```

**Fix**:
```rust
// ✅ AFTER (v0.9.29-beta - FIXED)
let address_hex = hex::encode(&address_bytes[..8]);  // First 8 bytes = 16 hex chars
```

**Expected Result**: Wallet balances will display correctly in frontend

### **FIX #2: Pointer Race Condition (2-Week Stall Bug)**
**Severity**: CRITICAL - Network blocking for weeks
**File**: `crates/q-storage/src/transaction.rs:174-209`

**Problem**:
- Network stuck at height 2505 for 2+ weeks
- `qblock:latest` pointer at 2505, but actual contiguous blockchain at 2001
- 504-block gap prevents block producer from finding parent blocks
- Caused by unconditional pointer updates when saving out-of-order blocks

**Root Cause**:
```rust
// ❌ BEFORE (v0.8.4-beta through v0.9.28-beta - BROKEN)
self.put("blocks", b"qblock:latest", &height_key).await?;
// Always updates pointer to ANY block height, even if out of order!
```

**Fix**:
```rust
// ✅ AFTER (v0.9.29-beta - FIXED)
let current_pointer = self.get_current_height_from_pointer().await?;

// Update pointer ONLY if block extends contiguous chain
if block.header.height == 0 || block.header.height == current_pointer + 1 {
    self.put("blocks", b"qblock:latest", &height_key).await?;
    debug!("✅ Updated qblock:latest pointer to {} (contiguous extension)", block.header.height);
} else {
    debug!("⏭️  Saved block {} but did NOT update pointer (current: {}, would create gap)",
           block.header.height, current_pointer);
}
```

**Expected Result**:
- Pointer never races ahead of contiguous chain
- Block producer never stalls due to missing parent blocks
- Network stable, no more 2-week stalls
