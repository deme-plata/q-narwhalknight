## Critical Bug: "Gap at Height 2" Infinite Loop

### Problem Statement
Fresh nodes syncing from the network get stuck in an infinite loop with these symptoms:
1. **Batch sync works**: Successfully downloads and stores 1600+ blocks to database
2. **Height never advances**: Node stays stuck at height 0 forever
3. **"Gap at height 2"**: Continuous warnings about missing height 1
4. **Block producers stuck at genesis**: "No blocks in storage yet - producers at genesis"
5. **Watchdog reports**: "Block producer healthy (height 0 -> 1)" 60 seconds after sync

### Root Cause Timeline

```
13:45:09 - Block producers initialize: "No blocks in storage yet - producers at genesis"
13:45:14 - Batch sync writes: "Updated qblock:latest pointer to 1748" ✅
13:45:15 - Batch sync writes: "Updated qblock:latest pointer to 800" ✅
13:45:15 - Batch sync writes: "Updated qblock:latest pointer to 1600" ✅
13:46:09 - Watchdog reports: "Block producer healthy (height 0 -> 1)" ❌
```

**60 seconds after batch sync stored 1600 blocks, producers still see height 0!**

### Technical Root Cause

**Storage Layer Isolation** - Block producers and batch sync use different storage views:

1. **Block producers** call `sync_from_storage()` **ONCE** at initialization
   - Read database: height = 0
   - Cache this height internally
   - Never refresh again

2. **Batch sync** writes blocks and updates database pointer
   - Stores blocks 1-1600 successfully
   - Updates `qblock:latest` pointer to 1600
   - **Never notifies block producers**

3. **Block producers continue** with cached height 0
   - Use stale height for all operations
   - Gap detection sees: current=0, incoming=1920, gap at height=2
   - Height validation never advances

### Code Location of Bug

**File**: `crates/q-api-server/src/main.rs`
**Lines**: 2684-2793

**Missing**: Block producer pool not cloned into batch sync task
**Impact**: Batch sync has no way to notify producers after completion



## Prevention Strategy

### Code Patterns to Follow

Whenever batch operations update storage, **ALWAYS** sync producers:

```rust
// ✅ CORRECT PATTERN
storage.batch_write(blocks).await?;
storage.update_pointer(height).await?;
block_producer_pool.sync_from_storage(&storage).await?; // ← MANDATORY

// ❌ WRONG PATTERN
storage.batch_write(blocks).await?;
storage.update_pointer(height).await?;
// Missing sync_from_storage() - producers will have stale view!
```

### Future Improvements

Consider for v0.9.102+:
1. **Periodic auto-sync**: Sync producers every 1000 blocks as backup
2. **Height drift detection**: Alert if producer height != database height
3. **Watchdog trigger**: Force sync if height unchanged for 60s
4. **Unified storage view**: Eliminate caching, always read from database

## Lessons Learned

1. **Cached State is Dangerous**: Never cache height without refresh mechanism
2. **Storage Isolation is Critical**: All components must see same data
3. **Batch Operations Need Notifications**: Producers can't detect batch changes
