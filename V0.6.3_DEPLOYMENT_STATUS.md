## 🔧 v0.6.3-beta Changes

### Critical Fix: Turbo Sync Protocol Corruption

**Problem:**
- Alpha syncing at 0.4 blocks/min (should be 1000-5000 blocks/min)
- Corrupted block pack requests with impossible heights (e.g., 1762021442 instead of 64)
- Root cause: Binary protocol version mismatch between different server deployments

**Evidence from Alpha Logs:**
```
🚀 [TURBO SYNC P2P] Received pack request for blocks 1762021442-52 (ID: 2D3KooW9ywWfb9XH)
❌ Failed to create pack: Requested range 1762021442-52 exceeds local height 1877
```

**Solution:**
1. Added `protocol_version` field to `BlockPackRequest` struct
2. Implemented `validate_version()` method (checks compatibility)
3. Implemented `detect_corruption()` method (catches impossible values)
4. Updated request creation to use `new()` constructor (enforces version)
5. Added validation in request handler (rejects corrupted/incompatible requests)

**Expected Performance Impact:**
- **Before**: 0.4 blocks/min (broken Turbo Sync)
- **After**: 1000-5000 blocks/min (2500-12500x faster)

**Files Modified:**
- `crates/q-storage/src/turbo_sync.rs` - Protocol versioning framework
- `crates/q-api-server/src/main.rs` - Request validation
- `Cargo.toml` - Version bump to 0.6.3-beta
