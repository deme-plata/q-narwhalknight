# v0.9.65-beta: Turbo Sync Serialization Format Incompatibility

**Date**: 2025-11-09
**Issue**: Same version (v0.9.65-beta) nodes cannot decode each other's turbo sync messages
**Root Cause**: Different serialization formats in use on same network
**Status**: 🚨 **CRITICAL** - Network fragmentation

---

## Problem Summary

**Symptom**: Nodes running identical v0.9.65-beta version cannot communicate via Turbo Sync

**Evidence**:

### Server Alpha (161.35.219.10) - SENDS postcard format
```
📤 [TURBO SYNC DEBUG] Sending BlockPackRequest:
   Protocol Version: 1
   Heights: 2435-3957
   Serialized bytes (len=62): [01 ... ]  # First byte = 0x01 (postcard)
```

### Bootstrap Server (185.182.185.227) - RECEIVES MessagePack format
```
❌ Failed to deserialize block pack request
Raw data: [148, 199, 191, 200, 6, 52, 49, 50, 68...]  # First byte = 0x94 (MessagePack array)
```

### Analysis

- **0x01**: Postcard serialization (varint for protocol_version=1)
- **0x94**: MessagePack array format (4-element array)

**Conclusion**: Different nodes are using **different serialization formats** despite claiming the same version.

---

## Root Cause: Build Environment Differences

### Hypothesis

Both nodes claim v0.9.65-beta but were compiled with different:
1. **Dependency versions** - Different postcard/MessagePack library versions

### Current Code (v0.9.65-beta)

**Sender** (`main.rs:1900`):
```rust
let pack_request = BlockPackRequest::new(start_height, end_height, request_id);
match postcard::to_allocvec(&pack_request) {  // ✅ ALWAYS postcard
    Ok(data) => {
        // Send via gossipsub
    }
}
```

**Receiver** (`turbo_sync.rs:161-345`):
```rust
pub fn from_bytes(data: &[u8]) -> Result<Self> {
    // ✅ v0.9.65: Tries MULTIPLE formats
    // 1. Postcard NEW format (protocol_version field)
    // 2. Postcard OLD format (no protocol_version)
    // 3. MessagePack OLD format
    // 4. Bincode NEW format
    // 5. Bincode OLD format

    // ALL formats should work...
}
```

**Expected Behavior**: Receiver tries postcard first, should succeed

**Actual Behavior**: Receiver gets MessagePack data (0x94 first byte)

### Why This Happens

**Scenario 1: Different Codepaths**
- Server Alpha uses: `postcard::to_allocvec()` at line 1900
- Bootstrap uses: Different serialization function (MessagePack?)

**Scenario 2: Different Binary**
- Server Alpha: Built from latest `main` branch
- Bootstrap: Built from older commit with same version tag

**Scenario 3: Environment Variables**
- One node has `Q_USE_MESSAGEPACK=1` flag set
- Different serialization selected at runtime

## Long-Term Fix: Protocol Version Enforcement

### Add Binary Hash to Version

```rust
// In lib.rs or version.rs
pub const VERSION: &str = "0.9.65-beta";
pub const BUILD_HASH: &str = env!("BUILD_HASH"); // Set at compile time

// In BlockPackRequest
pub struct BlockPackRequest {
    pub protocol_version: u32,
    pub build_hash: String,  // ✅ NEW - Enforce exact binary match
    pub start_height: u64,
    pub end_height: u64,
    pub request_id: String,
}

// Reject if build_hash doesn't match
if request.build_hash != BUILD_HASH {
    warn!("⚠️ Incompatible build: {} vs {}", request.build_hash, BUILD_HASH);
    return Err(anyhow!("Build mismatch"));
}
```

### Add Serialization Format Field

```rust
#[derive(Serialize, Deserialize)]
pub enum SerializationFormat {
    Postcard,
    MessagePack,
    Bincode,
}

pub struct BlockPackRequest {
    pub protocol_version: u32,
    pub serialization_format: SerializationFormat,  // ✅ NEW
    pub start_height: u64,
    pub end_height: u64,
    pub request_id: String,
}

// Sender declares format
let format = SerializationFormat::Postcard;
let request = BlockPackRequest { format, ... };

// Receiver uses correct deserializer
match request.serialization_format {
    SerializationFormat::Postcard => postcard::from_bytes(...),
    SerializationFormat::MessagePack => rmp_serde::from_slice(...),
    SerializationFormat::Bincode => bincode::deserialize(...),
}
```
