## 🐛 DOCKER NETWORKING ROOT CAUSE

### Possible Causes

#### 1. Docker Network Mode
**Issue**: Container using wrong network mode

**Check**:
```bash
# On Server Alpha
docker inspect <container_id> | grep NetworkMode
```

**Expected**: `"NetworkMode": "bridge"` or `"NetworkMode": "host"`

**Fix if wrong**:
```bash
# Use host networking for simplicity
docker run --network host ...
```

#### 2. DNS Resolution Failure
**Issue**: Container cannot resolve 185.182.185.227 or quillon.xyz

**Check**:
```bash
# Inside container
docker exec <container_id> ping -c 3 185.182.185.227
docker exec <container_id> curl -v http://185.182.185.227:8080
```

**Fix if failing**:
```bash
# Add DNS servers to Docker
docker run --dns 8.8.8.8 --dns 8.8.4.4 ...
```

#### 3. Firewall Blocking Outbound HTTP
**Issue**: iptables or firewall blocking outbound HTTP from Docker

**Check**:
```bash
# On Server Alpha host
iptables -L OUTPUT -v -n | grep -E "185.182.185.227|8080"
```

**Fix if blocked**:
```bash
# Allow outbound HTTP
iptables -I OUTPUT -p tcp --dport 8080 -d 185.182.185.227 -j ACCEPT
```

#### 4. Docker Bridge Network Misconfiguration
**Issue**: Docker bridge network cannot reach external IPs

**Check**:
```bash
# Inside container
docker exec <container_id> route -n
docker exec <container_id> ip route show
```

**Fix**:
```bash
# Restart Docker networking
systemctl restart docker
```

## 🔬 WHY THIS HAPPENED

### Docker Bridge Mode Isolation

**Default Docker networking**:
```
Container ──► Docker Bridge ──► iptables NAT ──► External Network
```

**Potential failure points**:
1. **Bridge routing**: Bridge may not have route to 185.182.185.227
2. **NAT translation**: iptables may block/drop HTTP requests
3. **DNS**: Container may not resolve external domains
4. **Firewall**: Host firewall may block Docker → external HTTP

**Host networking**:
```
Container ──► Host Network Stack ──► External Network
```

**No failure points**: Container uses host's working network stack directly

## 💡 KEY INSIGHTS

**Why Blocks Were Produced Locally**:
- Block producer doesn't require peers to run
- Produces blocks every 2 seconds regardless of network
- Blocks queued locally, never propagated

**Why InsufficientPeers Error**:
- Gossipsub requires minimum peers to publish (usually 1-2)
- Server Alpha has zero peers (bootstrap discovery failed)
- All gossipsub publishes fail immediately

**Why mDNS Didn't Work**:
- mDNS only discovers local network (same subnet)
- Server Alpha (161.35.219.10) and Server Beta (185.182.185.227) are on different networks
- mDNS cannot cross routers/subnets
