async fn download_and_apply_chunk(...) -> Result<()> {
    // ✅ Create oneshot channel for response
    let (response_tx, response_rx) = oneshot::channel();

    // ✅ Send network request via channel
    network_tx.send(NetworkRequest::RequestBlockPack {
        start_height,
        end_height,
        request_id: request_id.clone(),
        response_tx,  // Network handler will use this
    })?;

    info!("🌐 [TURBO SYNC P2P] Requested pack {}-{} via gossipsub",
          start_height, end_height);

    // ✅ Wait for response with timeout
    match tokio::time::timeout(self.config.chunk_timeout, response_rx).await {
        Ok(Ok(pack_result)) => {
            match pack_result {
                Ok(pack) => {
                    info!("✅ [TURBO SYNC P2P] Received pack {}-{}",
                          start_height, end_height);
                    pack  // Use the received pack
                }
                Err(e) => {
                    warn!("❌ [TURBO SYNC P2P] Pack request failed: {}", e);
                    // Fallback to local pack creation
                    self.create_block_pack(start_height, end_height).await?
                }
            }
        }
        Ok(Err(_)) => {
            warn!("⚠️ [TURBO SYNC P2P] Response channel closed");
            self.create_block_pack(start_height, end_height).await?
        }
        Err(_) => {
            warn!("⏱️ [TURBO SYNC P2P] Timeout waiting for pack");
            self.create_block_pack(start_height, end_height).await?
        }
    }

    // ✅ Apply the pack
    self.apply_block_pack(pack, None).await?;
    Ok(())
}
```

async fn download_chunks_parallel(...) -> Result<()> {
    let mut futures = FuturesUnordered::new();
    let mut completed_chunks = 0usize;

    // ✅ Create parallel download tasks
    for (chunk_idx, (start, end)) in chunks.into_iter().enumerate() {
        futures.push(tokio::spawn(async move {
            self_clone.download_and_apply_chunk(peer, start, end, retry_count).await
        }));
    }

    // ✅ Wait for ALL chunks to complete
    while let Some(result) = futures.next().await {
        match result? {
            Ok((start, end)) => {
                completed_chunks += 1;
                info!("📊 [TURBO SYNC] Progress: {}/{} chunks",
                      completed_chunks, total_chunks);
            }
            Err(e) => {
                error!("❌ Chunk failed: {}", e);
            }
        }
    }

    // ✅ Verify all chunks completed
    if completed_chunks < total_chunks {
        warn!("⚠️  Completed {}/{} chunks ({} failed)",
              completed_chunks, total_chunks, total_chunks - completed_chunks);
    }

    Ok(())
}
```

**Status**: ✅ WORKING - DOES wait for all futures!

## 🤔 WHY DO THE DESIGN FLAW DOCUMENTS EXIST?

The documents suggest TurboSync returns immediately without waiting. However, the code clearly shows:

1. **Line 980**: `while let Some(result) = futures.next().await` - WAITS for all tasks
2. **Line 879**: `tokio::time::timeout(self.config.chunk_timeout, response_rx).await` - WAITS with timeout
3. **Line 2640**: Response handler DOES deliver packs via oneshot channel

**Possible explanations**:
1. Documents are outdated (written before current implementation)
2. Analysis was based on logs showing fast completion (maybe local fallback was used?)
3. Issue was already fixed in a previous version

## 🔍 POTENTIAL ACTUAL ISSUES

If TurboSync is failing in practice, possible causes:

### 1. Gossipsub Message Delivery Issues
- Bootstrap node not receiving `/block-pack-requests` messages
- Fresh node not receiving `/block-pack-responses` messages
- Network connectivity problems

### 2. Response Map Mismatch
- Different response_map instances used for registration vs lookup
- Race condition between registration and response arrival

### 3. Timeout Too Short
- 30-second timeout might be insufficient for large block packs
- Network latency causing timeouts

### 4. Peer Discovery Issues
- `qualified_peers` list is empty → no peers to sync from
- Lines 1102-1116 check for this and bail if no peers found

### 5. Local Fallback Behavior
- Timeout causes fallback to `create_block_pack()` (line 904)
- This creates pack locally instead of downloading from peers
- Results in "sync" completing without actual P2P transfer
