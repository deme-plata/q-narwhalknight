## Lessons Learned

### Root Cause

**Problem:** Tokio executor starvation
- Blocking operations (`fsync()`, RocksDB flush) on executor threads
- Happens after 23 minutes when memtable fills (142MB)
- BlockWriter appears dead but is just starved
- SIGKILL during stall causes WAL corruption and data loss

### Solution

**Pattern:** Always use `spawn_blocking` for blocking I/O
```rust
// ❌ WRONG: Blocks executor thread
async fn write_batch(&self) {
    self.db.write_opt(batch, &opts)?;  // fsync() blocks 5-30s
}

// ✅ CORRECT: Offloads to dedicated thread pool
async fn write_batch(&self) {
    tokio::task::spawn_blocking(move || {
        db.write_opt(batch, &opts)?;
    }).await??;
}
```

### Prevention

**Watchdog Pattern:** Detect stalls early
- Receive timeout (10s) - Detects channel starvation
- Write timeout (30s) - Detects slow operations
- Circuit breaker (5 errors) - Prevents cascading failures
- Loud failures instead of silent deadlocks
